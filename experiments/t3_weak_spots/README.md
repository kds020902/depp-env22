# T3에서 보인 약점 고치기 (채택 안 함, TV-12 그대로)

시험지 T3에서 보인 약점 4가지를 고치려고 했다. 규칙은 사진을 모으기 전에 [PREREG.md](PREREG.md)에 적었다.

**약점:**
- 흙 묻은 정상 감자·당근을 상했다고 봄
- 곰팡이 핀 과일을 상한 감자로 봄
- 상한 토마토의 초기 증상을 정상으로 봄
- 껍질이 연한 고구마를 감자로 봄

**결론:**
- 1회차 후보 넷(K1~K4)과 2회차 후보 둘(L1·L2) 모두 채택 기준을 넘지 못했다. 그래서 **TV-12를 그대로 쓴다.**
- 새 봉인 시험지 T4(100장)는 아무 모델에도 돌리지 않았다. 다음 시도 때 그대로 쓸 수 있다.

## 사진

- **모은 곳:** iNaturalist와 Wikimedia Commons에서 새로 모았다.
    - 후보 약 8,300장 중 예전 사진과 같은 사진, CLIP으로 본 식물·잎·배양 접시 사진을 뺐다.
    - 남은 3,378장을 눈으로 봤다. 감자·토마토 2,665장은 subagent 4개가 보고, 직접 다시 확인했다.
- **역할 나누기:** 올린 사람 단위로 학습 / 개발용 / T4로 나눴다.

| 상한 감자 | 21 | 6 | 10 |

- **상한 과일:** "다섯 채소가 아님"으로 가르치면 상한 과일은 잘 거른다(9 → 27/30). 하지만 진짜 상한 감자·토마토도 같이 거른다.
    - 첫 인터넷 시험지에서 잃은 8장은 모두 상한 감자·토마토였다.
    - CLIP 특징에서 곰팡이 핀 과일과 곰팡이 핀 채소가 가까워서 생기는 일로 보인다.
    - 예전 후보 F1에서도 같은 일이 있었다. 이 방식으로는 두 번 실패했다.
- **흙 묻은 감자, 고구마:** CLIP 쪽 보강만으로 정상 감자 16 → 19, 고구마 7 → 9가 됐다. 다른 성능은 그대로였다(K3). 다만 늘어난 폭이 미리 정한 +10에 못 미쳤다.
- **상한 토마토 초기 증상:** 학습 사진이 19장뿐이라 거의 바뀌지 않았다(5 → 5~6/11).
- **채소 모델 다시 학습 (K2, K4):** 160장 시험지(밭·휴대폰 사진)가 4~7장 떨어졌다.

## 2회차: 상한 토마토를 더해서 (`dev_results2.json`)

- **새 사진:** iNaturalist에서 설명에 tomato·tomate·pomodoro가 들어간 곰팡이 관찰, 열매가 달렸다고 표시된 토마토 관찰을 더 찾았다.
    - 후보 663장 중 161장을 직접 봤다.
    - 상한 토마토 학습 17장, 개발용 5장을 더했다(학습 19 → 36장).
    - T4 몫 사진은 보지 않고 따로 뒀다.
- **후보:**
    - L1: K3 + 새 토마토
    - L2: L1 + 채소 모델 다시 학습

| | TV-12 | L1 | L2 |
|---|---:|---:|---:|
| 약점 점수 (개발용) | 45 | 52 (+7) | 54 (+9) |
| ┗ 흙 묻은 정상 감자 /20 | 16 | 19 | 19 |
| ┗ 정상 고구마 /10 | 7 | 9 | 9 |
| ┗ 상한 토마토 /16 | 8 | 10 | 12 |
| ┗ 상한 과일 거름 /30 | 9 | 9 | 9 |
| 160장 시험지 (−3 이내) | 146 | 146 | **136 ✗** |
| 판정 | | 개선 +7 < 10 | 탈락 |

- **L1:** 다른 성능은 그대로였다. 다만 개선 폭이 기준(+10)에 못 미쳤다.
- **채소 모델을 다시 학습하면 밭·휴대폰 사진(160장 시험지)이 떨어진다.** K2 −7, K4 −4, L2 −10으로 세 번 모두 같은 방향이었다.
    - 인터넷 관찰 사진을 채소 모델 학습에 더하는 방식은 이 사진들을 잃게 하는 것으로 보인다(추측).
- 기준은 결과를 본 뒤에 바꾸지 않았다.
- 고른 후보가 없어 T4는 2회차에도 쓰지 않았다.

## 이번 일의 한계

- **기준 +10이 사실상 상한 과일에만 기대고 있었다.**
    - 개발용 사진이 목표보다 적게 모여 정상 당근 5장은 처음부터 다 맞았다. 그래서 상한 과일을 빼면 더 늘 자리가 13장뿐이었다.
    - 기준은 사진 수를 알기 전에 정했다. 결과를 본 뒤 기준을 바꾸지는 않았다.
- 후보 K3·K4는 K1 결과를 본 뒤 더했다(PREREG 덧붙임 3). 그래서 개발용 사진에서 고르는 데 운이 조금 더 들어간다.

## 다음 시도

1. 상한 토마토 초기 증상 사진은 공개 사진으로 더 모으기 어렵다(2회차까지 학습 36장). 직접 찍은 사진이 필요하다.
2. 상한 과일은 "채소 아님"으로 가르치는 대신 다른 방법이 필요하다.
3. T4(봉인, 100장)는 다음 후보를 마지막에 한 번 재는 데 쓴다.

## 다시 돌리기

```bash
python experiments/t3_weak_spots/build.py check            # TV-12 다시 만들기 (같은지 확인)
python experiments/t3_weak_spots/build.py K1               # K3도 같은 방식
python experiments/t3_weak_spots/build.py data             # K2·K4 채소 모델 학습 목록
python src/train.py --manifest <k2data>/manifest.csv --out <K2_s42> --arch efficientnet_b0 --num-classes 10 --mode finetune \
    --epochs 30 --patience 8 --seed 42 --watermark-fresh 0.6 --watermark-rotten 0.3 --watermark-style light   # seed 43도
python experiments/t3_weak_spots/build.py K2               # K4도
python experiments/t3_weak_spots/evaluate.py K1 K2 K3 K4   # -> dev_results.json
```

사진과 목록은 작업 폴더에 있다(라이선스 때문에 저장소에 올리지 않음). 그래서 이 스크립트들은 기록용이다.
