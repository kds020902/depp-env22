# CLIP 분류기 학습 사진 균형 맞추기 (B1, 채택 안 함)

계획: [PREREG.md](PREREG.md) (덧붙임 1·2 포함). 만들기: `build.py lists`, `build.py B1`. 개발용 확인: `evaluate.py`.

## 한 것
- 형체가 무너진 상한 사진 78장을 뺐다.
- 채소마다 정상:상함을 1:1로 맞췄다(목록 [b1_counts.json](b1_counts.json)).

| 채소 | 정상 : 상함 (TV-12) | 정상 : 상함 (B1) |
|---|---|---|
| 토마토 | 429 : 562 | 429 : 429 |
| 감자 | 267 : 272 | 350 : 350 |
| 오이 | 408 : 267 | 350 : 350 (아시아 오이 140장 모두 유지) |
| 당근 | 225 : 235 | 350 : 350 |
| 피망 | 184 : 183 | 334 : 334 (인터넷까지 찾아도 350장에 못 미침) |

- 채운 사진: 약점 학습 몫 106장, 로컬 데이터셋 539장, 인터넷 67장(iNaturalist 20, Commons 41, 첫 웹 검색 6).
- B1은 CLIP 분류기만 다시 학습했다. 채소 모델과 새 채소 분류기는 TV-12 그대로다.

## 결론
- 전체 점수가 그대로라 채택하지 않았다. 새 블라인드 테스트셋(T5)도 만들지 않았다(사용자 결정).
- 해석: CLIP 분류기는 고정된 CLIP 특징 위의 로지스틱 회귀라, 클래스 수의 차이(최대 3.1배 → 1.3배)는 거의 영향이 없었다. 성능을 정하는 것은 사진 수보다 사진이 어떤 장면인지다.
