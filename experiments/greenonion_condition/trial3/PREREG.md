# 대파 상태 학습 3차 시험 (개발 단계만, 사전 등록 — 2차 결과를 본 뒤 정함)

2026-11-28. 결과를 보기 전에 커밋한다. **최종 시험용은 열지 않는다.** 같은 개발 자료를 세 번째 본다는 점을 밝힌다.

## 2차에서 본 것

- G1·G2 통과, G3 실패: 대파로 알아본 상한 대파 63장 중 37장(58.7%)만 "상함", 기준 60%에 1장 모자람. 정상 49/59.
- 사진 추가는 공개 웹에서 새로 확정된 상한 사진이 0장이라 할 수 없었다. 사용자가 2번(설정 변경)을 골랐다.

## 바꾸는 것 하나

- 두 번째 분류기를 학습할 때 상한 대파(15) 행의 가중치를 `정상 대파(14) 행 수 / 상한 대파(15) 행 수`로 둔다.
  다른 행은 모두 가중치 1. (전체 자료에서 14번 97+62 ≈ 159행, 15번 68행이라 약 2.3배. 접힘마다 그 접힘의 학습 행으로 계산.)
- 방법: `train15w.py`가 2차 `train15.py`와 같이 `UNTRAINED_CLASSES`를 비우고, `fit_head`만 위 가중치를 쓰는 판으로 바꿔 학습기를 그대로 실행.
- 사진 목록(`photos.csv`, 130장, 2차와 같은 사진)·특징·접힘·τ 0.8·결정 규칙·관문 G1·G2·G3은 2차와 같다.
  학습 전 무결성 검사(`integrity.py`)를 먼저 돌리고 실패하면 멈춘다.

## 후보와 멈춤 규칙

- 후보는 이 설정 **하나**뿐이다. 결과를 보고 가중치 값을 다시 고르지 않는다.
- G3을 통과하지 못하면(상한·정상 각각 60% 이상) **대파 상태 학습은 여기서 중지**하고, 웹은 지금처럼 대파 상태를 실험 기능으로 둔다.
- 통과해도 개발 자료를 세 번 본 결과라 낙관적일 수 있다. 채택 여부는 시험용 37장(정리 후)을 한 번 열어 정한다.

## 보고 방식 (2차 검수 반영)

- G1은 "전체 969장 합계"와 "대파를 뺀 기존 7종" 두 줄로 적는다.
- G2·G3은 확신 부족으로 보류된 사진도 포함한 값이며 웹 표시 성능이 아님을 적는다.
- 이 시험으로 `model.pth`, `labels.py`, 앱은 바꾸지 않는다.
