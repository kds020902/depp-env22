# 대파 상태 학습 1차 시험 (개발 단계만, 사전 등록)

2026-11-28. 결과를 보기 전에 커밋한다. CPU만 쓴다. **최종 시험용(test_holdout_open_once)은 열지 않는다.**

## 자료

- 사용자 데이터셋의 학습+개발(`../user_lists.csv`, split이 train·dev인 것): 상한 61, 정상 60. 사용자가 지운 사진과 제외·재검토 목록은 이미 빠져 있다.
- Codex 수집분 중 Claude가 확정한 것(`claude_review.csv`의 spoiled 7, fresh 2).
- 묶음(출처) = 사용자 데이터셋은 `source_id`, Codex 수집분은 `source_group`.
- 학습 직전에 `build_user_lists.py --check`가 실패하면 멈춘다.

## 후보 (두 번째 분류기만 다시 학습, 첫 단계·감자 재확인은 그대로)

- 학습기: `src/train_new_veg_head.py` 그대로(C=10, α=0.25, "아님" 95% 규칙, τ 0.8 고정).
- 학습 자료: `v7/head_data.npz` + 새 대파 사진(정상 → 클래스 14, 상한 → 클래스 15).
- 판정: 대파로 답한 사진의 상태는 두 번째 분류기의 14/15 중 큰 쪽.

## 개발 평가 (출처 단위 5겹 교차검증, 접힘 = sha1("go:"+출처) % 5)

접힘마다 그 접힘의 사진 없이 학습기 전체로 다시 학습하고, 그 접힘 사진을 전체 결정 규칙(`decision.decide`)으로 답한다.
TV-13(지금 모델)도 같은 사진에 그대로 적용한다.

보고하는 수(장수와 함께):
- **대파로 알아봄**: 거르지 않고 종류가 대파
- **상태 맞음**: 대파로 알아본 사진 중 상한→15, 정상→14
- 상한 사진을 "학습된 데이터가 아닙니다"로 거른 수

## 관문 (모두 통과해야 "가능성 있음"으로 보고, 아니면 멈추고 보고)

- **G1 기존 7종 퇴행 없음** (`tools/compare_on_dev.py`, 개발 969장, 전체 자료로 학습한 후보): 전체 맞음 ≥ 869, 상한 감자 ≥ 126, 정상 감자 ≥ 107, 상한을 정상으로 답한 수 ≤ 17.
- **G2 상한 대파를 대파로 알아봄**: 교차검증에서 상한 사진 중 "대파로 알아봄"이 TV-13보다 많다.
- **G3 상태 구분**: 교차검증에서 대파로 알아본 사진의 상태 맞음 비율이 상한·정상 각각 60% 이상.

## 미리 밝혀 둘 점

- 사진 대부분은 개인 블로그 사진이다. 공개 배포 여부는 사용자가 정한다. 이 시험은 로컬에서만 한다.
- 학습+개발 상한이 70장 남짓이라 결과는 흔들릴 수 있다. 최종 성능은 시험용 37장으로만 말한다.
