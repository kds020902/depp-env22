# 대파 정상·비정상 (진행 중)

TV-13은 대파의 종류만 판정한다. 상한 대파 학습 사진이 0장이라 두 번째 분류기의 `greenonion_rotten` 칸이 꺼져 있다.

## 0단계 (`prep.py`, `thresholds.json`)

상한 대파 사진 없이 할 수 있는 것만 했다. 정상 대파 117장(Train 97 + 새 채소 Valid 20)으로 기준선을 정했다.

- **zs (글 설명 점수):** CLIP ViT-B/16 사진 특징과 "시들고·물러지고·곰팡이 핀 대파" 문장들의 유사도에서 "싱싱한 대파" 문장들의 유사도를 뺀 값.
- **knn (정상과의 거리):** 정상 대파 학습 사진 중 가장 가까운 5장과의 코사인 거리. **배경·조명에도 반응하므로 검증 전에는 "이상 후보" 점수로만 본다**(Codex 지적).
- 기준선은 정상 117장의 95%가 정상으로 남는 값. **상한 대파를 얼마나 잡는지는 아직 측정하지 않았다.**
- 이 "95%"는 같은 117장에 맞춘 값이다. 새 정상 대파 사진에서 몇 %가 정상으로 남는지(독립 평가)는 따로 재야 한다(Codex 지적).
- 평가할 때 밭에서 병든 대파와 부엌에서 시들거나 무른 대파는 따로 집계한다.

## 1단계: 상한 대파 사진 (사용자 촬영이 주 자료)

공개 사진은 Openverse·iNaturalist·Wikimedia Commons에서 사실상 0장이었다(2026-11-29 확인).

촬영 기록 규칙:
- 사진마다 **대파 단 번호**, 촬영일, 상태(정상 / 시듦·변색 / 물러짐 / 곰팡이)를 적는다.
- 보고할 때 **사진 장수와 서로 다른 대파 단 수를 함께** 적는다. 단 수가 적으면 독립된 사례가 적은 것이므로 결과는 **예비 검증**이라고 쓴다.
- 학습용·시험용은 **대파 단 단위로** 나눈다(같은 단이 양쪽에 들어가지 않게).

보조 자료(agy가 찾은 농업 병해 도감·보관 가이드 사진)는 라이선스 표기가 없거나 저작권이 있다.
쓰더라도 저장소에 사진을 올리지 않고 주소·해시만 기록하며, 밭에서 병든 대파는 부엌에서 상한 대파와 모습이 달라 따로 집계한다.

## 통합할 때 함께 볼 것 (Codex)

- 학습 자료뿐 아니라 `labels.UNTRAINED_CLASSES`, `NO_CONDITION_SPECIES`, 헤드의 `no_condition_species`·`untrained_classes` 설정.
- 공통 학습기(`src/train_new_veg_head.py`)는 Codex와 조율한 뒤에 바꾼다.

## 첫 실측 (2026-11-28, 예비): 타키이 종묘 대파 병해 도감 사진

- agy가 찾은 도감 64장을 내려받아 눈으로 검수했다(사진은 저작권이 있어 저장소에 올리지 않음, 주소·해시만 `takii_manifest.csv`).
- 열리는 사진 중 같은 해시를 하나로 합쳐 **병든 대파 27장, 겉보기 정상 6장**. 모두 **밭에서 찍은 병해 사진**이라 부엌에서 상한 대파와는 다르다.
- 기준선(정상 대파 117장으로 정함)은 **바꾸지 않고** 그대로 적용했다. 이 사진으로 기준선을 조정하지 않았다.
- 이름: **고정된 기준선으로 본 밭 병해 예비 평가**. 재현: `python experiments/greenonion_condition/eval_takii.py 사진폴더` → `takii_eval.json`(사진별 점수·제외 이유).
- **상태 점수만:** 병든 대파 **21/27(78%)** 이 기준선 위. 겉보기 정상 6장 중 **2장에 경고**(건강이 확인된 사진이 아니라 "겉보기 정상에서 경고한 비율"이다).
- **웹 화면 전체(app.answer 규칙):** 병든 대파 **1/27** 만 "이상 징후 후보"가 보인다. 21장은 시스템이 "학습된 데이터가 아닙니다"로 거르고, 4장은 대파로 보되 판단 보류라 안내가 붙지 않는다. 겉보기 정상 6장은 0장.
- 즉 밭에서 병든 대파는 대부분 **대파로 알아보지도 못한다**. 상태 점수 자체보다 앞단(거르기·종류 판정)이 병목이다.
- 한계: 표본이 작고, 한 출처(도감 한 곳)이며, 라벨은 Claude가 눈으로 붙였다. 부엌에서 시들거나 무른 대파 성능은 여전히 모른다.
- 이 결과를 보고 문장이나 기준선을 바꾸면 이 사진들은 개발 자료로 취급한다(Codex).

## 부엌 사진 시도 (2026-11-28): agy가 찾은 페이지 16곳

- `fetch_pages.py`로 페이지의 사진을 모았다. 9곳은 열리지 않았고(HTTP 오류), 7곳에서 69장. 저작권 사진이라 저장소에 올리지 않았다.
- 상한 대파는 **2장**뿐(doesitgobad의 시들어 누런 대파 1장, 끈적하게 물러진 대파 1장). 나머지는 정상·썬 대파, 요리, 다른 채소, 관계없는 사진.
- 2장의 결과: 시든 대파는 상태 점수 기준선 아래, 시스템 답은 **토마토**. 물러진 대파는 상태 점수 기준선 위, 시스템은 **"학습된 데이터가 아닙니다"**. 웹 화면에는 둘 다 안내가 뜨지 않는다.
