# 감자·고구마 글 설명(CLIP 텍스트) 비교: 계획 (결과를 보기 전에 작성, 2026-11-22)

## 무엇을 묻나
- T8에서 TV-12는 상한 고구마 16장을 모두 "상한 감자"로 답했다(`results/t8_test`).
- **질문:** 가중치와 판정 기준을 그대로 두고, 감자·고구마의 **글 설명 문구만** 바꾸면 상한 고구마를 더 알아보는가?
- 이번 실험은 **다음 단계로 가져갈 문구가 있는지**만 본다. 채택은 하지 않는다. 채택은 새 블라인드 시험지와 사용자 검토가 있어야 한다.

## 글 설명이 쓰이는 곳 (코드에서 확인)
| 쓰임 | 위치 | 문구 |
|---|---|---|
| 클래스 판정 | `new_vegetable_head["text_embeddings"]` (16행), `decision.new_vegetable_logits` | 클래스마다 3~4문장의 평균. 로지스틱 회귀 점수에 0.25배로 더한다. **이번에 바꾸는 곳** |
| 거르기 | `clip_head["text_evidence"]`, `decision.text_evidence` | 다섯 채소 5단어와 다른 것 86단어. 고정 |
| 가까운 항목 안내 | `clip_model.TEMPLATES`, `ClipModel.message` | 거른 사진에 "…로 보입니다" 한 줄. 판정과 무관. 고정 |

- 다섯 채소용 CLIP 분류기(`clip_head`)에는 글 설명 점수가 없다(`alpha` 없음).
- 그래서 문구가 답을 바꿀 수 있는 길은 **두 번째 분류기가 고구마로 넘기는 단계** 하나뿐이다.

## 바꾸는 것 (변수 하나)
- `text_embeddings`의 16행 중 **감자·고구마 4행**(정상·상함)만 바꾼다. 나머지 12행은 TV-12 그대로다.
- **고정:** 채소 모델, 두 분류기의 가중치, α 0.25, 전환 기준 0.8, 거르기 기준 두 개, 표시 온도, 판단 보류 0.9
- 문구는 `prompts.json`에 있다. 감자와 고구마는 **문장 수와 문장 구조가 같고**, 채소 이름과 그 채소의 생김새만 다르다.

| 이름 | 내용 | 클래스당 문장 |
|---|---|---:|
| TV-12 | 지금 문구 (참고) | 정상 3, 상함 4 |
| P0 | 클래스 이름만 ("a photo of a rotten sweet potato.") | 1 |
| P1 | 사진 문맥을 붙임 (부엌 조리대, 시장·보관 상자, 가까이 찍음) | 3 |
| P2 | 눈에 보이는 특징 (모양, 껍질 색, 무른 반점·곰팡이·싹) | 3 |

- 임베딩은 TV-12와 같은 방법으로 만든다: 문장마다 정규화 → 평균 → 다시 정규화.
- **확인:** TV-12의 문구를 같은 코드로 다시 넣으면 저장된 임베딩과 같아야 한다(코사인 0.999 이상). 다르면 비교를 멈춘다.

## 개발 자료 (블라인드 시험지 T3~T8은 읽지 않는다)
- `tools/compare_on_dev.py`의 개발 세트 전부: 라벨 있는 969장 + 라벨 없는 966장
- 상한 고구마는 25장뿐이다(새 채소 Valid 9장 + 웹 16장). 한 장이 4%포인트다.
- **한계(미리 적음):** TV-12는 이 25장 중 18장을 이미 맞힌다(72%). T8에서는 0/16이었다. 즉 개발 사진은 T8보다 쉽고, 여기서 좋아져도 T8 같은 사진에서 좋아진다는 뜻이 아니다.

## 볼 숫자
1. **고구마 재현율:** 상한 고구마 25장 중 고구마로 답한 수(종류), 상한 고구마로 답한 수(클래스). 정상 고구마 63장도 같이 본다.
2. **감자를 고구마로 본 수:** 감자 259장(정상 126, 상함 133) 중 고구마로 답한 수
3. 상함 → 정상 오류(전체), 판단 보류율, 답을 낸 사진의 정확도, 다섯 채소 맞은 수
4. TV-12와 답이 달라진 사진 수(세트별)

## "다음 단계로 가져간다"의 조건 (TV-12 대비, 모두 만족)
- 상한 고구마를 고구마로 답한 수: **+2장 이상** (25장 중)
- 감자를 고구마로 본 수: **+1장 이내** (259장 중)
- 상함 → 정상 오류(라벨 있는 969장): TV-12 이하
- 다섯 채소 10개 클래스 맞은 수(827장): −2장 이내
- 과일 374장·일상 사진 400장 거른 수: 각각 −2장 이내

- 조건을 만족하는 문구가 여럿이면 상한 고구마 수가 많은 쪽, 같으면 감자 오인이 적은 쪽을 고른다.
- 만족하는 문구가 없으면 "문구만으로는 안 된다"로 적고 끝낸다. 조건을 결과에 맞춰 고치지 않는다.
- P0는 기준안이다. P0가 조건을 만족하면 "짧은 문구로 충분하다"는 뜻으로 그대로 적는다.

## 덧붙임 1 (2026-11-22, 결과를 본 뒤에 적음: Codex 검수 반영)
- 위 계획과 조건은 고치지 않았다. 아래는 뜻을 분명히 하는 것과 정정 수치다.
- **18/25와 21/25의 뜻:** "개발 자료"의 18장(72%)은 **종류와 상태를 모두** 맞힌 수(상한 고구마로 답함)다. 조건에 쓰는 수는 **종류만** 맞힌 수(고구마로 답함)이고, TV-12는 21장(84%)이다.
- **상함 → 정상 오류의 정의:** 처음 결과는 "같은 채소의 정상으로 답한 수"만 셌다. 상한 고구마를 "정상 감자"로 답한 경우가 빠지는 정의다. 기존 성적표(`results/scorecard`)처럼 "어느 채소든 정상으로 답한 수"도 함께 적는다.
    - 정정 수치: 두 정의 모두 TV-12, P0, P1, P2가 17/385로 같다. 조건의 판정은 달라지지 않는다.
    - 답을 낸 사진(판단 보류 제외)만 보면 넷 다 8장이다.

## 덧붙임 2 (2026-11-22, 결과를 본 뒤에 적음: 개발 사진의 학습 사진 닮음)
- **실수:** 감자·고구마 웹 사진 162장을 "TV-12 학습에 쓰지 않았다"고 적었다. 파일은 쓰지 않았지만, 9장은 TV-12 새 채소 분류기의 학습 사진과 CLIP 코사인 0.95 이상으로 닮았다(정상 고구마 6장, 상한 고구마 3장, 모두 iNaturalist. 0.99 이상은 1장).
    - 원래 중복 검사(`experiments/root_and_tomato/build.py dedup`)가 시험지·데이터셋·개발 사진과만 비교하고, 분류기 학습 특징(`head_data.npz`의 `train_X`)과는 비교하지 않았기 때문이다.
- **이 9장을 뺀 정정 수치 (상한 고구마 22장 → 고구마로 답함):** TV-12 19, P0 18, P1 17, P2 20. 차이는 −1, −2, +1장으로 처음과 같다. 조건(+2장)의 판정은 달라지지 않는다.
- 감자 109장과 나머지 개발 세트(인터넷 221, 160장, 아시아 오이, 새 채소 Valid, 과일, 일상, 실제 장면)에는 0.95 이상이 0~1장이다. Valid의 11장은 같은 데이터셋의 Train과 닮은 것이다(알려진 세션 겹침).
- `dev_features.npz`는 그대로 둔다(기준선 기록이 이 파일을 가리킨다). 다음 실험은 이 9장을 뺀 수도 함께 적는다.
