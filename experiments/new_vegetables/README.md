# 양파·고구마·대파 추가 (8종): 채택 V6-H

다섯 채소(오이·감자·토마토·피망·당근)에 양파·고구마·대파를 더했다.
- 정한 것:
    - 비정상에는 곰팡이·무름뿐 아니라 **싹 난 것**도 넣는다.
    - 상한 대파 사진은 공개된 것이 없어서, **대파는 종류만 알아보고 상태는 판정하지 않는다**.
- 사진은 직접 찍기 어려워 인터넷 공개 사진을 모아 하나씩 눈으로 검수했다.
- 다섯 번의 후보를 거쳐 **V6-H를 채택**했다(`model.pth`의 `new_vegetable_head`).

## 판정 방식 (V6-H)

1. **지금 시스템이 먼저 답한다.** 채소 모델(EfficientNet-B0, 10클래스)과 CLIP 분류기(N3)를 합치고, R1로 거른다.
2. **지금 시스템이 거른 사진**은 새 CLIP 분류기(16칸 + "여덟 채소가 아님")가 다시 본다.
    - 새 분류기가 "아님"이라고 하지 않고, 가장 그럴듯한 종류가 양파·고구마·대파이면 그 답을 쓴다.
    - 종류는 정상과 비정상 확률을 더해서 고른다.
3. **지금 시스템이 답한 사진**은 바꾸기 어렵게 했다.
    - 새 분류기가 양파·고구마·대파 여섯 칸에 준 확률의 합이 **0.7 이상**일 때만 새 분류기의 답으로 바꾼다.
4. 그 밖에는 지금 시스템의 답을 그대로 쓴다.
    - 대파는 "대파 (상태 판정 안 함)"으로 보여 준다.
    - 히트맵(상한 곳 보기)은 채소 모델이 아는 다섯 채소에만 있다.

이렇게 한 이유는 V4-R 실패 때문이다. 새 분류기가 종류를 먼저 고르게 했더니, 처음 보는 기존 채소 사진(상한 토마토, 감자)을 양파·고구마로 잘못 보냈다.

## 데이터 (`photos.csv`, 사진마다 출처·라이선스·올린 사람·주소)

- **출처:**
    - iNaturalist
    - Openverse(Flickr 등)
    - Wikimedia Commons
    - Kaggle kritikseth(CC0)
    - LVIS 실제 장면에서 잘라낸 사진(MIT)
- **검수와 중복:**
    - 모두 눈으로 검수했다.
    - 예전 사진(봉인 시험지 포함)과 CLIP 코사인 0.95 이상인 복사본, 새 사진끼리의 복사본은 뺐다.
- **나누기:**
    - 올린 사람(관찰자, 원본 사진) 단위로 나눴다.
    - 기존 봉인 시험지에 사진을 올린 사람은 시험지 쪽에만 둔다.
    - 회차마다 새로 시험지로 가는 사진은 클래스마다 1/3까지다.
- 사진 파일은 라이선스가 제각각이라 올리지 않았다.

## 한계

- **상한 고구마는 아직 약하다(7/16).**
    - 실제 학습 사진이 32장뿐이다. 공개 사진을 끝까지 찾았지만 더 없었다.
    - 증강(V6-A)은 상한 고구마에서는 10/16으로 나았지만, 개발용 사진에서는 나아지지 않았고 다른 곳이 조금 나빠졌다.
- **대파는 33장 중 22장이다.** 놓친 사진은 대부분 걸렀다.
- **감자를 고구마로 답하는 경우가 남아 있다.**
- **시험지를 여러 번 썼다.** Test는 11번, 새 인터넷 시험지는 6번 채점했다. 기존 채소 실력은 새 봉인 시험지로 다시 재는 것이 좋다.
- 정상/비정상 판정은 새 CLIP 분류기 혼자 한다. 다섯 채소처럼 채소 모델과 합치지 않는다.

## 파일

- `photos.csv`: 검수한 사진 605장
    - 열: 회차(round), 나누기(split), 클래스, 출처, 라이선스, 올린 사람(attribution), 원래 페이지, 받은 주소, 그룹
- `v4/`, `v5/`, `v6/`: 회차마다 사전등록(`PREREG.md`), 사진 묶기(`build_pool.py`), 개발용 확인, 마지막 채점(`final.py`, `final_once.json`)
- `v6/build_checkpoint.py`: 채택한 V6-H 분류기를 `model.pth`에 넣은 스크립트
- `v6/export_photos.py`: 사진 목록을 쓴 스크립트
- 스크립트는 작업 폴더의 경로를 그대로 담고 있어서 기록용이다.
