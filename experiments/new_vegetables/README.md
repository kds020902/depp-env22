# 양파·고구마·대파 추가 (8종): 채택 V7 = TV-10

다섯 채소(오이·감자·토마토·피망·당근)에 양파·고구마·대파를 더했다.
- 정한 것:
    - 비정상에는 곰팡이·무름뿐 아니라 **싹 난 것**도 넣는다.
    - 상한 대파 사진은 공개된 것이 없어서, **대파는 종류만 알아보고 상태는 판정하지 않는다**.
- 사진은 직접 찍기 어려워 인터넷 공개 사진을 모아 하나씩 눈으로 검수했다.
- 여러 후보를 거쳐 **V7을 채택**했다(`model.pth`의 `new_vegetable_head`). 버전 이름으로는 V6-H가 TV-9, V7이 TV-10이다. 지금 TV-11도 이 분류기를 그대로 쓴다.

## 판정 방식 (V7)

1. **지금 시스템이 먼저 답한다.** 채소 모델(EfficientNet-B0, 10클래스)과 CLIP 분류기(N3)를 합치고, R1로 거른다.
2. **두 번째 CLIP 분류기**(16칸 + "여덟 채소가 아님")의 점수는 로지스틱 회귀 점수에 **CLIP 글 설명 점수**를 0.25배 더한 값이다.
    - 글 설명 점수: 사진과 클래스별 글 설명("a photo of a sprouting sweet potato.", "a photo of green onions." 등)의 CLIP 유사도(zero-shot)
3. **지금 시스템이 거른 사진**은 새 분류기가 다시 본다. "아님"이 아니고 가장 그럴듯한 종류가 양파·고구마·대파이면 그 답을 쓴다. 종류는 정상과 비정상 확률을 더해서 고른다.
4. **지금 시스템이 답한 사진**은, 새 분류기가 양파·고구마·대파 여섯 칸에 준 확률의 합이 **0.8 이상**일 때만 답을 바꾼다.
5. 그 밖에는 지금 시스템의 답을 그대로 쓴다.
    - 대파는 "대파 (상태 판정 안 함)"으로 보여 준다.
    - 히트맵(상한 곳 보기)은 채소 모델이 아는 다섯 채소에만 있다.

이렇게 한 이유는 V4-R 실패 때문이다. 새 분류기가 종류를 먼저 고르게 했더니, 처음 보는 기존 채소(상한 토마토·감자)를 양파·고구마로 잘못 보냈다.

    - LVIS 실제 장면에서 잘라낸 사진(MIT)
- **검수와 중복:**
    - 모두 눈으로 검수했다.
    - 예전 사진(봉인 시험지 포함)과 CLIP 코사인 0.95 이상인 복사본, 새 사진끼리의 복사본은 뺐다.
- **나누기:**
    - 올린 사람(관찰자, 원본 사진) 단위로 나눴다.
    - 기존 봉인 시험지에 사진을 올린 사람은 시험지 쪽에만 둔다.

- 사진 파일은 라이선스가 제각각이라 올리지 않았다.

## 한계

- **상한 고구마는 아직 약하다(23장 중 15장, 95% 신뢰구간 45~81%).** 싹 난 고구마를 "감자 비정상"으로 보는 경우가 가장 많다. 다섯 채소 시스템이 감자로 답하면 새 분류기가 80% 이상 확신해야 바꾸기 때문이다.
- **감자를 고구마로 답하는 경우도 남아 있다**(새 인터넷 시험지 3장).
- **시험지를 여러 번 썼다.** Test는 13번, 새 인터넷 시험지는 8번 채점했다(13·8번째는 [워터마크 2회차](../watermark/README.md)). 기존 채소 실력은 새 봉인 시험지로 다시 재는 것이 좋다.
- **이후 바뀐 점:** 워터마크 2회차(WC, TV-11)에서 다섯 채소 부분(채소 모델·CLIP 분류기)을 다시 학습했다. 새 채소 분류기는 그대로이고, τ는 같은 규칙으로 다시 골라 0.8이 나왔다. 8종 결과는 Test 287 / 284, 새 인터넷 시험지 199 / 189, 새 채소 시험지 176장이다.
- **라이선스가 없거나 "all rights reserved"인 iNaturalist 사진 75장을 썼다**(학습 47, Valid 7, 시험지 21). `photos.csv`에서 license가 비었거나 attribution에 "all rights reserved"가 있는 사진이다. 다시 만들 때 빼는 것이 좋다.
- 정상/비정상 판정은 새 CLIP 분류기 혼자 한다. 다섯 채소처럼 채소 모델과 합치지 않는다.

## 다시 만들기

```bash
python src/train_new_veg_head.py --model model.pth --data experiments/new_vegetables/v7/head_data.npz
```

- `model.pth`의 다섯 채소 부분은 그대로 두고, `new_vegetable_head`만 다시 만든다.
- 채택한 V7과 가중치가 똑같이 나온다(차이 0).
- `--alpha 0`이면 글 설명을 섞지 않는다.

## 파일

- `photos.csv`: 검수한 사진 700장
    - 열: 회차(round), 나누기(split), 클래스, 출처, 라이선스, 올린 사람(attribution), 원래 페이지, 받은 주소, 그룹
- `v4/` ~ `v7/`: 회차마다 사전등록(`PREREG.md`), 사진 묶기(`build_pool.py`), 개발용 확인, 마지막 채점(`final.py`, `final_once.json`)
- `v7/head_data.npz`: 새 채소 분류기를 다시 만드는 데 필요한 CLIP 특징·라벨·개발용 점수·글 설명
- `v7/export_head_data.py`, `v7/export_photos.py`: 위 두 파일을 만든 스크립트
- `v7` 이전 스크립트는 작업 폴더의 경로를 그대로 담고 있어서 기록용이다.
