# 새 채소 사진 더 모으기 (v5), 결과를 보기 전에 적음 (2026-10-31)

V4-R은 새 인터넷 시험지에서 기존 채소 11장을 새 채소로 잘못 보내 채택 조건을 넘지 못했다(상한 토마토 → 상한 양파, 감자 → 고구마).
사용자 요청("이미지를 더 추가해보자 새 채소")에 따라 새 채소 사진을 더 모았다.
판정 방식도 기존 채소를 덜 건드리도록 바꾼 후보를 만든다.

## 데이터 (`pool.json`, 사진마다 출처·라이선스·올린 사람)

- v4 사진 315장의 나누기는 그대로 둔다.
- 이번에 196장을 더 눈으로 검수했다. 출처는 iNaturalist, Openverse(Flickr 등), 위키미디어 공용, LVIS 실제 장면에서 잘라낸 사진이다.
    - 예전 사진(봉인 시험지 포함)과 CLIP 코사인 0.95 이상인 2장을 뺐다.
    - 새 사진끼리 겹치는 9장을 뺐다.
    - 그래서 185장이 남았다.
- 나누기 규칙은 v4와 같다.
    - 올린 사람(관찰자, 원본 사진) 단위로 나눈다.
    - v4에 이미 있던 사람은 v4와 같은 쪽에 둔다.
    - 기존 봉인 시험지에 사진을 올린 사람은 시험지 쪽에 둔다.
    - 새로 시험지로 가는 사진은 클래스마다 1/3까지다.
- 이번에 시험지 쪽으로 간 54장은 **새 채소 시험지 2**로 봉인한다. v4의 97장은 **새 채소 시험지 1**이고, V4-R 채점에 한 번 썼다.

## 후보 V5-H

1. **채소 모델:** 지금 `model.pth`(10클래스)를 그대로 쓴다. V4에서 다시 학습한 채소 모델은 기존 채소 점수를 떨어뜨렸다.
2. **새 CLIP 분류기 (16칸 + "아님"):**
    - V4와 같은 방법(다항 로지스틱 회귀, C=10)으로, 새 채소 Train 279장을 넣어 다시 학습한다(`head_v5.pkl`).
    - "아님" 기준도 같은 규칙으로 정했다. Valid 기존 300장, 새 채소 Valid 58장, 실제 장면 채소 192장의 95%가 통과하는 값으로, −1.031이다.
3. **판정 순서 (V4-R의 실패를 보고 바꿈):**
    1. 지금 시스템(채소 모델 + N3 CLIP 분류기, R1 거르기)이 먼저 답한다.
    2. 지금 시스템이 **거른** 사진은 새 CLIP 분류기가 다시 본다. "아님"이 아니고 가장 그럴듯한 종류가 양파·고구마·대파이면 그 답을 쓰고, 아니면 그대로 거른다.
    3. 지금 시스템이 **답한** 사진은, 새 CLIP 분류기가 양파·고구마·대파 여섯 칸에 준 확률의 합이 **0.7 이상**이고 가장 그럴듯한 종류가 새 채소일 때만 새 분류기의 답으로 바꾼다.
    - 그 밖에는 지금 시스템의 답을 그대로 쓴다.
    - 대파는 "대파 (상태 판정 안 함)"으로 보여 준다.
4. **0.7을 고른 방법 (개발용 사진만 씀):**
    - 0.5, 0.7, 0.8, 0.9, 0.95 중 가장 낮은 값을 골랐다.
    - 조건은 기존 채소 개발용 사진 910장(Valid 300, 인터넷 채소 221, 160장 시험지, 아시아 오이 37, 실제 장면 채소 192)에서, 지금 시스템이 답한 사진을 3번 규칙으로 새 채소로 바꾸는 수가 1장 이하인 것이다.
    - 0.5에서는 6장, 0.7에서는 1장이었다(`sweep.py`).

- R5는 V4-R과 같은 라우터에 새 CLIP 분류기(v5)만 바꿔 끼운 것이다. 사진을 늘린 효과만 보려고 같은 때에 한 번 채점해 기록한다.
- 어떤 결과가 나와도 R5는 채택하지 않는다.

## 미리 밝혀 둘 점

- 새 인터넷 시험지는 이번이 다섯 번째 채점이다. 후보를 고르는 데 쓰지는 않았지만 여러 번 본 시험지다. 기존 채소의 실력을 새로 재려면 새 봉인 시험지가 필요하다.
- 상한 고구마 Train은 22장뿐이라 고구마의 정상/비정상 판정은 믿기 어렵다.
- 개발용 새 채소 Valid에서 V5-H는 42/58(72%)이었다. 고구마를 지금 시스템이 감자로 받는 경우가 남아 있어서, 75% 조건을 넘지 못할 수 있다.
