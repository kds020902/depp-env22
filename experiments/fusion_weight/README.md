# 두 모델을 합치는 비중 다시 정하기 (W, 채택 안 함)

상한 토마토를 더 맞히려고, 채소 모델과 CLIP 분류기를 합치는 비중을 다시 정해 봤다. 미리 정한 개발용 확인에서 떨어져서 봉인 시험지는 열지 않았다. `model.pth`는 그대로다.

## 왜 했나

- 지금 시스템은 두 모델의 로그 확률을 1:1로 더한다.
- 인터넷 채소 221장(개발용)의 상한 토마토 45장에서 맞힌 수는 다음과 같다.
    - 채소 모델만: 17장
    - CLIP 분류기만: 40장
    - 합친 결과: 32장
- 채소 모델이 인터넷 사진에서 틀릴 때도 확률 97~100%로 강하게 틀려서, CLIP의 맞는 답을 덮는다.

## 바꾼 것 (`PREREG.md`)

- 합치는 식을 (w · 채소 모델 + CLIP 분류기) / T로 바꿨다.
- w와 T는 평가에 쓰지 않는 사진으로 정했다. Valid와, CLIP 분류기 학습에 더한 사진 1,773장의 교차 검증 예측에서 교차 엔트로피가 가장 낮은 값이다.

## 결과 (`check_results.json`)

고른 값은 w = 0.05로, 사실상 CLIP 분류기만 쓰는 셈이다.

| 개발용 확인 | 지금 (w = 1) | W (w = 0.05) |
|---|---:|---:|
| 인터넷 채소 221장 | 199 | **206** |
| 그중 상한 토마토 45장 | 32 | **40** |
| **160장 시험지** (기준 148 이상) | 150 | **130 ✗** |
| 그중 정상 토마토 20장 | 19 | 11 |
| Valid 300장 | 291 | 290 |
| 아시아 오이 37장 | 34 | 36 |

- **두 모델이 서로 다른 곳에서 강하게 틀린다.**
    - 채소 모델은 인터넷의 상한 토마토를 "정상 토마토"로 본다.
    - CLIP 분류기는 160장 시험지의 정상 토마토(천 위에서 휴대폰으로 찍은 덜 익은 주황색 토마토) 20장 중 12장을 "상한 토마토"로 본다.
- 그래서 비중만 바꾸면 한쪽을 고칠 때 다른 쪽이 망가진다.
    - `curve.py`로 w를 바꿔 보면, 160장 시험지가 기준을 넘는 w(0.6~0.7)에서는 상한 토마토가 37장으로 조금만 좋아진다.
    - 이 탐색은 결과를 본 뒤에 한 것이라 후보로 쓰지 않았다.
- 다음 시도: [fruit_farm_tomato](../fruit_farm_tomato/README.md)에서 CLIP 분류기에 농가 토마토 사진을 가르친 뒤 같은 방법으로 비중을 다시 정했다(F2). 여전히 160장 시험지에서 떨어졌다.

`fuse.py`와 `curve.py`는 작업 폴더의 경로를 그대로 담고 있어서 기록용이다.
