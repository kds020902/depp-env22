# 추가 실험: 일부만 상한 채소 잡기

결과: **채택하지 않았다.** 10가지 후보 중 학습 전에 정한 기준을 넘은 것이 없어서 Test는 한 번도 열지 않았다. 최종 모델(`model.pth`)은 그대로다.

## 왜 했나

꼭지 둘레만 곰팡이가 핀 토마토처럼 "대부분 멀쩡하고 일부만 상한" 채소를 최종 모델이 정상으로 판단하는 경우가 있었다. 이런 사진을 더 잘 잡을 수 있는지 모델 구조, 입력 크기, 데이터를 바꿔 가며 시험했다.

## 어떻게 평가했나

실험하는 동안 Test 180장은 열지 않았다. 실험용 manifest에서 Test 행을 지우고 Train·Valid만 남겼다. 후보는 아래 개발용 세트로만 골랐다.

- **Valid 180장:** 기존 분할 그대로
- **부분 부패 확인용 61장** (`partial_rot_dev_set.csv`)
    - 학습에 쓰지 않은 원본 사진 중 "대부분 멀쩡하고 일부만 상한" 사진을 눈으로 골랐다.
    - 토마토 28장, 감자 14장, 오이 19장이다. 모두 비정상이다.
- **밭 토마토 어려운 사례 60장:** [field_tomato 실험](../field_tomato/README.md)의 `hard_case_set.csv` (비정상 30, 정상 30)
- **꼭지 곰팡이 토마토 사진 1장:** 참고용으로만 봤다. 1장이라 기준에는 넣지 않았다.

채택 기준은 학습 전에 정했다.

1. Valid 6클래스 166/180 이상 (현재 모델과 같거나 높게)
2. Valid 정상 유지 82/90 이상 (오경보는 현재 모델보다 최대 1장 더)
3. 부분 부패 61장 중 58장 이상 (현재 모델은 57장)
4. 어려운 사례에서 비정상 27/30 이상, 정상 26/30 이상

1~4를 모두 넘은 후보만 Test 180장으로 한 번 채점하고, Test 6클래스 170/180 이상이면서 정상 유지 87/90 이상일 때만 채택하기로 했다.

## 해 본 것과 결과

학습 설정은 최종 모델과 같다(EfficientNet-B0 전체 미세조정, 같은 하이퍼파라미터). 판정 기준값은 0.5다. 같은 내용이 `dev_results.csv`에 있다.

- **추가한 데이터:** `added_train_photos.csv`
    - 부분 부패: 토마토 25, 오이 17, 감자 24장
    - 정상: 같은 수만큼. 현재 모델이 "비정상일 수도" 하고 헷갈려한 정상 사진을 골라 오경보도 줄이려 했다.
    - 출처: 두 Kaggle 데이터셋에서 기존 1,200장에 쓰지 않은 사진이다.
    - 두 번째 Kaggle 데이터셋의 토마토는 장식 틀과 회전 자국이 있어서, 안쪽 사진만 잘라 썼다(`preprocessing` 열).
- **부분 부패는 좋아지지 않았다:** 어떤 후보도 현재 모델의 57장을 넘지 못했다(50~55장).
- **시작값(seed)에 따른 흔들림이 크다:** 같은 설정에서 seed만 바꿔도 부분 부패 점수가 1~3장 달라졌다. 현재 모델의 57장에도 운이 섞였을 수 있다.
- **데이터 추가는 전체 정확도를 올렸다:**
    - Valid 6클래스가 166 → 172~173장, Valid 정상 유지가 83 → 87~89장으로 좋아졌다.
    - 다만 이번 기준은 부분 부패를 잡는 것이라 채택 대상이 아니었다. 그래서 Test로 확인하지도 않았다.
- **평균·최대 풀링은 역효과였다:** 밭 토마토 비정상 검출이 27장에서 17장까지 떨어졌다.
- **판정 기준값을 낮춰도 안 됐다:**
    - "세 채소 추가" 후보에 한해, 판정 기준값을 0.5에서 0.3까지 낮춰 보는 방법도 미리 정해 두고 시험했다.
    - seed 7 모델은 기준값 0.3에서 부분 부패 59장을 잡았지만, 밭 토마토 정상이 24/30으로 떨어졌다.
    - 나머지 두 후보는 0.3까지 낮춰도 부분 부패가 57장 이하였다.
- **계속 놓친 사진:** 세 가지 유형이었다.
    - 화면에서 작게 찍힌 토마토의 작은 구멍·멍
    - 싹이 길게 난 감자
    - 반점이 옅은 오이

## 중복 검사에서 발견한 것

- **추가 후보 129장 검사:**
    - 비교 대상: Train·Valid·Test·부분 부패 확인용·어려운 사례 사진 전부
    - 판정 기준: 반전·회전에 상관없는 특징 유사도 0.90 이상, 해시 거리, ORB 특징점 30개 이상 일치 중 하나라도 걸리면 같은 사진으로 봤다.
    - 결과: 36장을 뺐다. 그중 2장은 Test 사진과 같은 사진이었다.
- **"토마토 추가" 실험의 사진 58장도 같은 방법으로 다시 검사했다.**
    - 1장은 Test 사진을 잘라낸 것이었고, 1장은 Valid 사진과 같았다.
    - 그래서 "토마토 추가" 두 후보의 Valid 점수는 최대 1장 부풀었을 수 있다.
    - 마지막 "세 채소 추가" 실험에서는 이 2장을 뺐다.
    - Test는 열지 않았으므로 Test 점수에는 영향이 없다.

## 다음에 할 일

- **직접 찍은 사진:** 실제로 쓸 환경(조명, 카메라, 거리)에서 일부만 상한 채소를 직접 찍어 모아야 한다. 인터넷 사진은 대부분 "완전히 썩은" 사진이라 이 유형이 적다.
- **상한 부위 표시:** 사진 전체에 "비정상" 표시만 하는 대신 상한 부위에 상자를 그려 두면, 작은 반점만 보는 탐지 모델을 학습할 수 있다.
- **"확인 필요" 구간:** 모델을 바꾸지 않고 판정 기준을 두 단계로 나누는 방법도 있다. 예를 들어 비정상 점수가 0.2~0.5인 사진을 "확인 필요"로 표시한다.
    - 현재 모델로 계산하면 부분 부패 61장 중 60장이 "비정상 또는 확인 필요"로 잡힌다.
    - 대신 Valid 정상 90장 중 14장(지금은 7장)이 "비정상 또는 확인 필요"로 표시된다.

## 다시 실행하기

`added_train_photos.csv`의 사진을 원본 데이터셋에서 받아 `dataset/manifest.csv`의 Train에 더하고, Test 행은 지운 manifest를 `dataset/manifest_plus_partial.csv`로 저장해 학습한다. 기존 행의 `image_path`가 `dataset/` 기준이라 이 파일도 `dataset/`에 둔다.

```bash
python src/train.py --manifest dataset/manifest_plus_partial.csv --num-classes 6 --out results/effb0_plus_partial_s42 --arch efficientnet_b0 --mode finetune --epochs 30 --patience 8 --seed 42
python src/train.py --manifest dataset/manifest_plus_partial.csv --num-classes 6 --out results/effb0_plus_partial_s7 --arch efficientnet_b0 --mode finetune --epochs 30 --patience 8 --seed 7
```

가중치는 채택하지 않아서 올리지 않았다.
