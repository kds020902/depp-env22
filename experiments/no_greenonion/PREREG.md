# 대파 없애기: 8가지 → 7가지 채소 (결과를 보기 전에 적음, 2026-11-03)

## 사용자 결정 (2026-11-03)
- "모델에서 대파 없애기"를 골랐다.
- 대파는 썩은 사진을 찾지 못해 지금도 "대파"인지만 답하고 상태는 판정하지 않는다.

## 무엇을 바꾸나 (후보 G1)
- **새 채소 분류기만 다시 학습한다.** 채소 모델, CLIP 분류기(다섯 채소), 판정 규칙, τ 0.8, 판단 보류는 그대로다.
    - 대파 학습 사진 97장은 정답을 "여덟 채소 아님"(모르는 것)으로 바꿔 가르친다. 그래서 대파 사진은 걸러진다.
        - 화면에는 "학습된 데이터가 아닙니다 — 대파로 보입니다"가 나온다.
    - 대파 두 칸(정상·상함)은 학습하지 않은 클래스로 둔다. 클래스 번호는 그대로 둔다(예전 모델과 호환).
    - 거르기 기준(95% 통과)과 표시 온도를 맞출 때 쓰는 새 채소 Valid에서 대파 20장을 뺀다. 이 사진은 이제 걸러야 맞기 때문이다.
- **코드:** `src/train_new_veg_head.py`에 `--untrained` 옵션을 더한다(학습하지 않은 클래스를 더 지정). 판정 코드는 바꾸지 않는다.
- **채택되면 바꿀 것:** `labels.py`(대파를 학습 안 한 클래스로), `predict.py` 안내 문구(7종), README.

## 개발 확인 (T3·T4·T5는 이미 쓴 시험지라 개발 사진; 나머지는 `head_data.npz`의 저장된 특징)

| 볼 것 | 기준 (TV-12 대비) |
|---|---|
| **대파 사진 33장**(T3 10, T5 3, 새 채소 Valid 20)을 거름 | **80% 이상(27장 이상) 거름** |
| 대파 사진을 다른 채소로 답한 수 | 6장 이하 |
| 양파·고구마 종류 맞힘 (T3·T4·T5 48장) | −2장 이내 |
| 양파·고구마 종류 맞힘 (새 채소 Valid, 대파 뺀 69장) | −2장 이내 |
| 다섯 채소: Valid 300 / 인터넷 221 / 아시아 오이 37 맞게 남김 | −3 / −3 / −2 이내 |
| 일상 사진 400장 거름 | −5 이내 |
| 상한 과일 거름 (T3·T4·T5 83장) | −3 이내 |

- 모두 지키면 G1을 "통과"로 본다.
- 블라인드 테스트셋 T6는 토마토 후보와 합친 마지막 후보로만 한 번 채점한다([tomato_crops/PREREG.md](../tomato_crops/PREREG.md)).
- 반영(TV-13)은 사용자가 정한다.

## 개발 결과 (2026-11-03, [dev_results.json](dev_results.json))
- **G1은 조건을 모두 지켰다.**
    - 대파 33장 중 31장(94%)을 거른다. TV-12는 4장을 걸렀다.
    - 나머지 2장은 양파로 답한다. TV-12는 4장을 양파로 답했다.
    - 양파·고구마, 다섯 채소, 거르기, 상한 과일, "예전 채소 → 새 채소"는 TV-12와 같다.
- T6 채점은 토마토 후보 결정과 함께 정한다(T6는 한 번만 쓸 수 있으므로).
