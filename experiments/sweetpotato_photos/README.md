# 상한 고구마 학습 사진 추가 (SP1): 반영 안 함 — 개발 확인에서 탈락, T9는 열지 않음

- **결론:** 상한 고구마 학습 사진 21장을 더한 후보 SP1은 **개발 사진의 안전 조건 두 개를 어겼다.** 감자를 고구마로 답하는 실수가 늘었다. 계획대로 블라인드 시험지 T9는 채점하지 않았다.
- `model.pth`(TV-12)는 바뀌지 않았다.
- 계획과 그동안의 덧붙임은 [`PREREG.md`](PREREG.md)에 있다. 조건은 사진이 오기 전에 적었다.

## 바꾼 것 (변수 하나)
- 새 채소 분류기(`new_vegetable_head`)의 학습 행에 상한 고구마 사진 21장을 더했다(44장 → 65장). 학습 방법과 나머지는 TV-12 그대로다(`build.py`).
- 사진을 더하지 않고 같은 방법으로 다시 만들면 TV-12의 분류기가 그대로 나온다(가중치 차이 0).

| 학습 사진의 출처 묶음 | 장 수 |
|---|---:|
| Scot Nelson | 10 |
| Gerald Holmes | 5 |
| NARO | 5 |
| University of Delaware | 1 |

- 21장 모두 기존 사진(개발, 학습, T3~T9)과 CLIP 코사인 0.95 미만이다. T9 사진과의 최댓값은 0.855다.

## 개발 확인 결과 (`dev_results.json`, 블라인드 시험지는 읽지 않음)

| 조건 (TV-12 대비) | 기준 | TV-12 | SP1 | 판정 |
|---|---|---:|---:|---|
| 감자 259장을 고구마로 답한 수 | +1장 이내 | 2 (0.8%) | 5 (1.9%) | **어김 (+3)** |
| 다섯 채소 맞은 수 (827장) | −2장 이내 | 745 (90.1%) | 742 (89.7%) | **어김 (−3)** |
| 상함 → 정상 오류 (385장, 어느 채소든) | TV-12 이하 | 17 | 17 | 지킴 |
| 상한 고구마 25장을 고구마로 답한 수 | −1장 이내 | 21 (84%) | 21 (84%) | 지킴 |
| 과일 374장 / 일상 400장 거른 수 | 각각 −2장 이내 | 347 / 400 | 346 / 400 | 지킴 |

- **달라진 답은 1,935장 중 10장이다.** 같은 사진에서 맞음 → 틀림 5장, 틀림 → 맞음 2장.
    - 감자 → 상한 고구마: 3장(상한 감자 2, 정상 감자 1). 세 장 모두 TV-12는 맞혔다.
    - 상한 고구마 4장이 서로 반대로 바뀌었다(2장은 감자 → 고구마로 고쳐졌고, 2장은 고구마 → 감자로 나빠졌다).
    - 과일 1장(거름 → 상한 고구마), 과일 1장(상한 감자 → 상한 고구마), 실제 장면 채소 1장(상한 오이 → 상한 고구마)
- 판단 보류율(17.0% → 16.9%)과 답을 낸 사진의 정확도(95.9% → 95.5%)는 거의 같다.
- 학습 사진과 닮은 3장을 뺀 상한 고구마 22장으로 봐도 TV-12 19장, SP1 19장으로 같다.

## 읽는 법
- 상한 고구마 사진을 더하자 분류기가 "상한 고구마"를 더 쉽게 답하게 됐고, 그 영향이 감자와 다른 사진으로 번졌다. 개발 사진의 상한 고구마는 늘지 않았다(TV-12가 이미 84%).
- 분류기를 만들 때 나오는 "기존 채소를 새 채소로 옮긴 수"가 전환 기준 0.8에서 TV-12는 1장, SP1은 3장이다(0.9에서는 0장). TV-12는 0.8을 고정해서 쓰고 이번 실험도 0.8을 고정했다.
- **T9에서 좋아졌을지는 모른다.** 개발 조건은 T9를 열기 전의 안전 확인이었고, 어겼으므로 열지 않았다.

## 다음에 해 볼 수 있는 것 (추측, 사용자 결정)
- **같은 사진 + 전환 기준을 규칙대로(0.9):** 분류기 학습 스크립트의 원래 규칙("기존 채소 개발 사진을 1장 이하로 옮기는 가장 작은 기준")을 쓰면 0.9가 된다. 감자 오인은 줄겠지만 상한 고구마를 고구마로 넘기기도 어려워진다. 변수가 다른 새 실험이라 계획을 따로 적어야 한다.
- 상한 감자 사진을 함께 더해 두 채소의 경계를 가르치는 것. 사진이 더 필요하다.
