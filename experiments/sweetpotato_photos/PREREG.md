# 상한 고구마 학습 사진 추가: 계획 (사진이 오기 전에 작성, 2026-11-22)

- **상태:** 계획과 제작 스크립트만 있다. 사진이 아직 없어서 후보도 결과도 없다.
- 채택은 사용자가 결정한다. 이 문서는 그 전에 무엇을 보고 어떤 조건을 쓸지 정한다.

## 무엇을 묻나
- T8에서 TV-12는 상한 고구마 16장을 모두 "상한 감자"로 답했다. 문구만 바꿔서는 달라지지 않았다(`experiments/sweetpotato_prompts`).
- **질문:** 새 채소 분류기의 학습 사진에 상한 고구마를 더 넣으면, 처음 보는 상한 고구마를 고구마로 답하는가? 감자를 고구마로 잘못 보지는 않는가?

## 바꾸는 것 (변수 하나)
- `new_vegetable_head`의 학습 행에 **상한 고구마 사진만** 더한다(지금 44장).
- **고정:** 채소 모델, 다섯 채소용 CLIP 분류기, 거르기 기준, 글 설명 문구와 비중(0.25배), 전환 기준 0.8, 판단 보류 0.9, 학습 방법(`src/train_new_veg_head.py --tau 0.8`)
    - 다시 학습하면 "여덟 채소가 아님" 기준과 표시 온도는 같은 규칙으로 다시 맞춰진다(TV-12를 만들 때와 같다).
- **확인해 둔 것:** 사진을 하나도 더하지 않고 같은 방법으로 다시 만들면 TV-12의 분류기가 그대로 나온다(가중치 차이 0, 개발 사진 1,935장 중 달라진 답 0장). 그래서 차이가 생기면 더한 사진 때문이다.
- 후보 이름은 SP1이다. 감자 사진, 정상 고구마 사진, 문구, 기준은 이번에 건드리지 않는다. 필요하면 다음 실험으로 따로 한다.

## 사진 나누기 (모델에 넣어 보기 전에)
1. 사용자가 보낸 사진을 **출처(사이트·올린 사람) 단위**로 묶는다. 같은 출처의 사진은 한쪽에만 둔다.
2. 출처 이름의 SHA-256 순서로 줄을 세워, 상한 고구마의 절반가량(최소 30장)이 찰 때까지 **새 블라인드 시험지 T9** 쪽에 먼저 넣는다. 나머지가 학습용이다.
3. 감자(상함, 흙 묻은 정상)와 그 밖의 사진은 모두 T9 쪽이다(이번에는 학습에 넣지 않는다).
4. **중복 제거(사진끼리의 닮음만 본다):** CLIP 코사인 0.95 이상이면 뺀다.
    - 학습용: 개발 사진, 지금 학습 행, T3~T8과 데이터셋 사진, 먼저 넣은 새 사진과 비교 (`build.py`)
    - T9: 위 전부와 새 학습 사진과 비교
5. 개발 사진의 상한 고구마 16장(웹)과 9장(새 채소 Valid)은 학습에 넣지 않는다.

## 개발 확인 (T9를 열기 전의 안전 확인)
- 도구: `python tools/compare_on_dev.py OUT.json SP1=후보.pth` (분류기만 바뀌므로 저장된 개발 자료를 쓸 수 있다)
- 개발 사진은 T8보다 쉽다(TV-12가 이미 상한 고구마 84%를 고구마로 답한다). 그래서 여기서는 **나빠지지 않는지**만 본다.

## T9 (새 블라인드 시험지, 한 번만 채점)
- 규칙은 `results/t9_test/RULES.md`에 따로 적고, 목록을 봉인(SHA-256)한 뒤 TV-12와 SP1을 한 번 채점한다.
- 워터마크·AI 의심 표시가 없는 사진("깨끗한 사진")으로 판정한다. T8과 같다.

| "채택을 제안한다"의 조건 (TV-12 대비, 모두 만족) | 기준 |
|---|---|
| 상한 고구마를 고구마로 답한 수 | **+20%포인트 이상** (30장이면 +6장) |
| 감자(상함 + 흙 묻은 정상)를 고구마로 답한 수 | +2장 이내 |
| 상한 감자 맞은 수 | −1장 이내 |
| 상함 → 정상 오류 (어느 채소든) | TV-12 이하 |
| 전체 채소 맞은 수 | TV-12 이상 |

- 조건을 만족해도 채택은 사용자가 결정한다. 만족하지 못하면 "반영 안 함"이다.
- T3~T8은 읽지 않는다. T8의 상한 고구마 16장은 TV-12의 오류를 이해하는 데만 썼다.

### 나누기 (묶음은 모든 클래스를 통틀어 한쪽에만)
1. **상한 고구마가 3장 이상인 묶음:** 학습용이다.
2. **상한 고구마가 1~2장인 묶음:** 묶음 이름의 SHA-256 순서로 보면서, 합이 **정확히 30장**이 되는 묶음들을 T9로 고른다. 여러 조합이 가능하면 "앞 순서의 묶음을 넣고도 30장을 채울 수 있으면 넣는다"로 정해지는 조합을 쓴다. 나머지는 학습용이다.

3. **상한 고구마가 없는 묶음:** T9용이다.
4. **학습 쪽 묶음의 다른 사진**(예: 같은 사람이 찍은 감자)은 쓰지 않는다. T9에 넣으면 같은 출처가 양쪽에 걸치고, 이번 실험은 상한 고구마만 더하기 때문이다. 제외 사유를 `split.json`에 남긴다.
