# TTV_1: 교수님 피드백대로 단계를 나눈 예시 모델 (계획, 결과를 보기 전에 적음)

2026-11-25. 사용자 지시: "바꾸지 말고 교수님 피드백으로 예시 TTV_1을 하나 만들어 굴려 봐라. 시험지에 썼던 데이터는 빼고 하나씩 넣어 봐라."
`model.pth`(TV-13)와 판정 코드는 바꾸지 않는다. TTV_1은 채택 후보가 아니라 구조를 비교해 보는 예시다.

## 묻는 것

1. 종류와 상태를 한 번에 답하는 대신 단계로 나누면, 자료를 더 넣을 때 다른 종류가 떨어지는 일이 줄어드는가?
2. 상한 고구마가 나아지는가?

## 방법 (`run.py`)

자료는 `experiments/new_vegetables/v7/head_data.npz`의 CLIP 특징(6,271행)과 `tools/compare_on_dev.py`의 개발 세트뿐이다.
T3~T9의 사진, 특징, 결과는 학습에도 채점에도 쓰지 않는다.

**TTV_1 (단계형)**: 모두 CLIP 특징 위의 로지스틱 회귀(C=10)다.
- 1단계 채소인가: 여덟 채소 대 그 밖(`not_eight`). 기준은 그 시점까지 넣은 종류의 Valid 사진 95%가 통과하는 값.
- 1.5단계 어떤 채소인가: 그 시점까지 넣은 종류 가운데 하나.
- 2단계 정상인가: 종류마다 따로 만든 정상/비정상 분류기. 대파는 상태를 판정하지 않는다.
- 3단계 상한 곳: 이번에는 재지 않는다(지도는 TV-13의 것을 그대로 쓰는 부분이다).

**FLAT (한 번에)**: 같은 행으로 학습한 한 개의 분류기(클래스 전부 + 그 밖). 거르는 기준은 같은 규칙.
**TV-13**: 참고용. 다시 학습하지 않는다(EfficientNet-B0와 글 설명 점수를 함께 쓰므로 위 둘과 조건이 다르다).

**하나씩 넣는 순서** (누적):
1. `not_eight` + `train1260` (다섯 채소 기본)
2. + `reviewed_extra`
3. + `asian_cucumber`
4. + `weak_spots`
5. + 양파 (`new_vegetables` 중 양파와, 같은 묶음의 감자·당근 12행)
6. + 고구마
7. + 대파

## 재는 것 (단계마다, TTV_1과 FLAT 각각)

- 클래스별 맞은 수(개발 사진 969장), 전체 맞은 수, 상한 것을 정상이라고 답한 수.
- 걸러야 할 사진(과일 374, 일상 400)을 거른 수와 거르면 안 되는 사진(실제 장면 채소 192)을 남긴 수.
- **앞 단계보다 맞은 수가 줄어든 클래스의 수와 줄어든 장수**, 같은 사진에서 맞음 → 틀림으로 바뀐 수. 이것이 질문 1의 답이다.
- 아직 넣지 않은 종류의 사진은 그 단계의 집계에서 뺀다.
- 7단계에서 TTV_1의 오류를 단계별로 나눈다: 1단계에서 걸러짐 / 종류를 틀림 / 종류는 맞고 상태를 틀림.

## 미리 적는 한계

- 개발 사진은 TV-13을 고를 때 쓴 사진이고, 감자·고구마 웹 162장 중 9장은 학습 행과 거의 같다. 결과는 "이 구조에서 이런 경향이 보였다"까지다.
- 클래스당 사진이 5~70장이다. 1~3장의 오르내림은 우연과 구분되지 않는다. 표에는 장수를 그대로 적는다.
- TTV_1과 FLAT은 EfficientNet-B0를 쓰지 않는다. TV-13보다 점수가 낮은 것은 구조 때문이 아니라 그 차이일 수 있다. 구조 비교는 TTV_1 대 FLAT으로 한다.
- 어느 쪽이 좋게 나와도 채택하지 않는다. 채택하려면 새 봉인 시험지가 필요하다.

## 덧붙임 1 (2026-11-25, TTV_1 결과를 본 뒤, 아래 결과를 보기 전): TTV_2

사용자 지시: "분류기를 나눠 보거나, 2단계도 지도를 개선해 봐라." TTV_1에서 고구마를 넣으면 정상 감자가 105 → 100으로 떨어졌고,
틀린 것의 54%가 2단계(상태)였다. 두 가지를 따로 바꿔 본다(`run2.py`). 자료와 금지 사항은 위와 같다.

### 가. "어떤 채소인가" 분류기 나누기 (1단계와 2단계는 TTV_1 그대로)

- **K-OVR**: 종류마다 "이 채소인가 아닌가" 분류기를 따로 둔다. 가장 점수가 높은 종류를 고른다.
- **K-FROZEN**: 새 종류를 넣을 때 앞 종류들의 분류기는 다시 학습하지 않고 그대로 둔다. 새 종류는 자기 분류기(새 종류 대 앞 종류 전부)의
  확률이 0.8 이상일 때만 사진을 가져간다. 0.8은 TV-13의 전환 기준을 그대로 쓴 값이고 이 실험에서 고르지 않는다.
- **K-PAIR**: TTV_1의 분류기를 쓰되, 1등과 2등이 감자와 고구마이면 감자 대 고구마 전용 분류기가 정한다.

재는 것: 고구마를 넣는 단계에서 떨어진 클래스와 장수, 맞음 → 틀림, 정상 감자, 고구마 맞은 수. 다 넣은 뒤의 전체 맞은 수.
K-FROZEN은 구조상 앞 종류끼리의 답이 바뀌지 않는다. 볼 것은 고구마가 가져가는 사진 수와 고구마 자체를 얼마나 맞히는가다.

### 나. 2단계에 채소 모델의 상한 흔적 더하기 (S2+E)

저장된 자료에는 상한 곳 지도 자체는 없고, 지도를 요약한 값인 EfficientNet-B0의 출력(`b`)이 있다. 다섯 채소(오이·감자·토마토·피망·당근)에 대해
상태 점수 = CLIP 상태 분류기 점수 + w × (b의 그 채소 비정상 − 정상)으로 한다. w는 {0, 0.5, 1, 2, 4} 중 Valid 300에서 상태를 가장 많이 맞히는 값
(같으면 작은 값). Valid는 w를 고른 사진이므로 결과는 Valid와 나머지를 나눠 적는다.

양파·고구마·대파는 EfficientNet-B0가 배우지 않아 이 방법을 쓸 수 없다. 고구마의 상한 곳 지도를 만들어 2단계에 쓰려면 사진과
CLIP 패치 특징이 필요하고, 이번 실행에는 넣지 않는다.

### 한계

위와 같다. 가·나 어느 것도 채택 후보가 아니다. w와 구조를 개발 사진에서 본 것이므로 좋게 나와도 새 시험지 없이는 확정하지 않는다.

## 덧붙임 2 (2026-11-25, TTV_2 결과를 본 뒤, 아래 결과를 보기 전): 고구마용 상한 흔적 (SPE)

사용자 지시: "고구마용 상한 흔적 해 봐. 우선 임시 폴더 사진을 써 보자." TTV_2에서 남은 빈칸은 고구마의 2단계에 더할 증거가 없다는 것이었다.

### 사진 (임시 폴더에 남아 있는 것. 저장소에는 올리지 않는다)

| 묶음 | 장수 | 출처 목록 |
|---|---:|---|
| 정상 고구마 | 42 | `experiments/root_and_tomato/new_train.csv` |
| 상한 고구마 | 16 + 21 | 같은 목록 16, `experiments/sweetpotato_photos/split.json`의 train 21 |
| 사용자 사진 2차의 상한 고구마 | 15 | `results/user_photos_2/photos.csv` (potato_check에서 이미 개발 자료로 쓴 사진) |
| 감자 (정상 62, 상함 54), 사용자 사진 2차의 흙 묻은 감자 26 | | 규칙이 감자 답을 건드리지 않는지 확인용 |

이 사진들은 TV-13의 학습에 들어가지 않았다(R1·R2·SP1은 반영하지 않은 후보였다). T3~T9 사진은 쓰지 않는다.
시작하기 전에 전체 사진 특징이 `bank_t3_t8_dataset.npz`의 어떤 행과 코사인 0.95 이상이면 뺀다(겹침 확인에만 씀).

### 방법 (`run3.py`): 학습 없이, TV-13에 들어 있는 것만으로

1. 사진을 가로·세로 절반 크기의 칸 9개(3×3, 절반씩 겹침)로 자른다.
2. 칸마다 CLIP 특징을 뽑아 TV-13의 `new_vegetable_head`에 넣고, **상한 고구마 점수 − 정상 고구마 점수**를 그 칸의 상한 흔적으로 한다. 이 9개 값이 지도다.
3. 사진의 상한 흔적 E = 9칸 중 최댓값.
4. 규칙 SPE: TV-13이 "정상 고구마"라고 답했고 E > 0이면 "상한 고구마"로 바꾼다. 0은 "그 칸이 정상보다 상한 쪽에 가깝다"는 뜻이고 이 사진들에서 고른 값이 아니다.
5. 보조 규칙 SPE2: 둘째로 큰 칸도 0보다 클 때만 바꾼다.

### 재는 것

- TV-13 그대로일 때와 SPE·SPE2일 때: 상한 고구마를 상했다고 답한 수(묶음별), 정상 고구마를 정상이라고 답한 수, 감자 답이 바뀐 수.
- 기준값을 −2 ~ 4로 바꿨을 때 "상한 고구마를 더 잡은 수 / 정상 고구마를 잘못 바꾼 수"(참고용 곡선. 여기서 기준을 고르지 않는다).
- 지도 예시 몇 장(사용자 확인용, 저장소에는 올리지 않음).

### 한계

- 사진이 적다(정상 42, 상함 52). 묶음마다 출처가 달라 묶음 사이의 차이가 사진 종류의 차이일 수 있다.
- 사용자 사진 15장은 이미 한 번 본 개발 자료다. 정상 고구마는 한 출처(iNaturalist)뿐이다.
- 채택 후보가 아니다. 좋게 나오면 새 봉인 시험지를 만들어 확인하는 것을 제안한다.
