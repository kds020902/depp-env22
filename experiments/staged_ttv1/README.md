# TTV_1: 단계를 나눈 예시 모델 (채택 후보 아님)

계획: [PREREG.md](PREREG.md). 결과: [results.json](results.json). 다시 돌리기: `python experiments/staged_ttv1/run.py experiments/staged_ttv1/results.json`

교수님 피드백("한 번에 밀지 말고 다단계로")대로 ① 채소인가 → 어떤 채소인가 → ② 정상인가를 따로 판정하는 TTV_1을 만들어,
같은 자료로 한 번에 답하는 FLAT과 비교했다. 학습 자료는 한 묶음씩 넣었다. T3~T9는 쓰지 않았다. `model.pth`는 바꾸지 않았다.

## 결과: 단계를 나누는 것만으로는 달라지지 않았다

| 일곱 묶음을 다 넣은 뒤 (개발 사진 969장) | TTV_1 (단계형) | FLAT (한 번에) | TV-13 (참고) |
|---|---:|---:|---:|
| 맞음 | 827 (85.3%) | 833 (86.0%) | 869 (89.7%) |
| 상한 것을 정상이라고 답함 | 15 | 13 | 17 |
| 과일 374장 중 거름 | 318 | 346 | 347 |
| 실제 장면 채소 192장 중 남김 | 185 | 172 | 172 |
| 상한 고구마 25장 | 17 | 16 | 18 |
| 정상 고구마 63장 | 55 | 55 | 51 |
| 정상 감자 126장 | 101 | 102 | 107 |

TV-13은 EfficientNet-B0와 글 설명 점수를 함께 써서 조건이 다르다. 구조 비교는 TTV_1 대 FLAT이다.

## 질문 1: 자료를 넣을 때 다른 종류가 덜 떨어지는가 → 아니다

| 넣은 묶음 | TTV_1: 떨어진 클래스 / 장수 | FLAT: 떨어진 클래스 / 장수 | TTV_1 맞음→틀림 / 틀림→맞음 | FLAT 맞음→틀림 / 틀림→맞음 |
|---|---:|---:|---:|---:|
| + reviewed_extra | 2 / 18 | 1 / 10 | 26 / 42 | 27 / 78 |
| + asian_cucumber | 3 / 6 | 2 / 4 | 10 / 9 | 6 / 10 |
| + weak_spots | 0 / 0 | 1 / 2 | 10 / 65 | 6 / 62 |
| + 양파 | 2 / 2 | 0 / 0 | 7 / 29 | 3 / 17 |
| **+ 고구마** | **3 / 9** | **7 / 12** | 15 / 19 | 14 / 4 |
| + 대파 | 1 / 2 | 2 / 4 | 5 / 6 | 5 / 8 |

고구마를 넣으면 두 구조 모두 정상 감자가 떨어진다(TTV_1 105 → 100, FLAT 106 → 102). 단계형은 떨어지는 클래스 수가 적지만(3 대 7)
같은 사진에서 맞던 것이 틀리는 수는 같다(15 대 14).

이유: 단계를 나눠도 "어떤 채소인가" 단계에서는 감자와 고구마가 여전히 같은 분류기 안에서 경쟁한다. 나눠서 지켜지는 것은
"감자의 정상/비정상 판정이 고구마 사진에 영향받지 않는다"뿐이다.

## 질문 2: 상한 고구마가 나아지는가 → 아니다

17 / 16 / 18장(25장 중)으로 세 구조가 같다. 1장 차이는 우연과 구분되지 않는다.

## TTV_1은 어느 단계에서 틀리는가 (틀린 142장)

| 단계 | 틀린 장수 | 비율 |
|---|---:|---:|
| 1단계에서 걸러짐 | 31 | 22% |
| 종류를 틀림 | 34 | 24% |
| **종류는 맞고 상태를 틀림** | **77** | **54%** |

상태를 틀린 77장 가운데 59장이 정상을 상했다고 한 것이다(정상 감자 19, 정상 피망 19, 정상 토마토 15, 정상 당근 6).
상한 고구마 8장 중 6장도 종류는 맞히고 상태를 틀렸다. 병목은 구조가 아니라 **2단계가 보는 특징**이다.

## 읽을 때 주의

- 개발 사진은 TV-13을 고를 때 쓴 사진이다. 감자·고구마 웹 162장 중 9장은 학습 행과 거의 같다.
- 클래스당 5~133장이다. 1~3장 차이는 우연과 구분되지 않는다.
- 2단계 분류기는 CLIP 특징 위의 로지스틱 회귀 하나씩이다. 2단계에 다른 입력(더 큰 해상도, 상한 부분을 잘라 보기, EfficientNet-B0의 상한 곳 지도)을 쓰는 것은 해 보지 않았다.
- 3단계(상한 곳 표시)는 재지 않았다.

# TTV_2: 분류기 나누기와 2단계에 상한 흔적 더하기 (채택 후보 아님)

계획: [PREREG.md](PREREG.md) 덧붙임 1. 결과: [results2.json](results2.json). 다시 돌리기: `python experiments/staged_ttv1/run2.py experiments/staged_ttv1/results2.json`

## 가. "어떤 채소인가" 분류기를 나누면

| 고구마를 넣는 단계 | TTV_1 | K-OVR (종류마다 따로) | K-PAIR (감자 대 고구마 전용) | K-FROZEN (앞 종류 고정, 새 종류는 0.8 이상만) |
|---|---:|---:|---:|---:|
| 맞음 → 틀림 | 15 | 15 | 17 | **2** |
| 정상 감자 (넣기 전 105) | 100 | 101 | 99 | **106** |
| 정상 고구마 / 63 | 55 | 54 | 54 | 37 |
| 상한 고구마 / 25 | 17 | 16 | 17 | 10 |
| 다 넣은 뒤 전체 / 969 | 827 | 822 | 823 | 810 |

- 분류기를 종류별로 나누거나 감자 대 고구마 전용 분류기를 두는 것(K-OVR, K-PAIR)은 효과가 없다. 여전히 같은 특징으로 같은 경계를 긋는다.
- **앞 종류를 고정하면(K-FROZEN) 다른 종류가 떨어지지 않는다**(맞음 → 틀림 15 → 2, 정상 감자 유지). 대신 고구마를 덜 가져가서
  고구마 자체는 55 → 37, 17 → 10으로 내려간다. 떨어뜨리지 않는 것과 새 종류를 잘 맞히는 것을 맞바꾼 것이다.
- K-FROZEN은 TV-13이 이미 쓰는 방식이다(`new_vegetable_head`의 전환 기준 0.8). TV-13은 여기에 글 설명 점수를 더해 같은 개발 사진에서
  정상 고구마 51, 상한 고구마 18, 정상 감자 107이다.

## 나. 2단계에 채소 모델의 상한 흔적을 더하면 (S2+E)

w는 Valid 300에서 0.5로 정해졌다(상태 맞음: w=0일 때 286, 0.5일 때 287, 1일 때 286 / 295장. 차이가 1장이라 w의 선택 자체는 근거가 약하다).

| | TTV_1 | S2+E (w=0.5) | TV-13 (참고) |
|---|---:|---:|---:|
| 전체 맞음 / 969 | 827 | **846** | 869 |
| 정상을 상했다고 답함(같은 종류) | 63 | **41** | |
| 상한 것을 정상이라고 답함 | 15 | 18 | 17 |
| Valid 300 (w를 고른 사진) | 277 | 278 | |
| 현장 160 | 119 | **141** | |
| 인터넷 221 | 195 | 192 | |
| 감자·고구마 웹 162 | 131 | 130 | |
| 새 채소 Valid 89 | 72 | 72 | |

- 2단계에 EfficientNet-B0의 상한 흔적을 더하면 19장이 오른다. 거의 전부 현장 사진(+22)이고, 정상을 상했다고 하는 오답이 63 → 41로 준다.
- 반대 방향의 오답(상한 것을 정상이라고 함)은 15 → 18로 3장 늘었다.
- 양파·고구마·대파는 EfficientNet-B0가 배우지 않아 이 방법이 닿지 않는다. 고구마 숫자는 그대로다.

## 정리

- 구조를 나누는 것 자체는 효과가 없었고, 효과가 있었던 것은 **앞 종류 고정**과 **2단계에 다른 종류의 증거(상한 흔적) 더하기** 둘이다.
- 이 둘은 TV-13에 이미 들어 있다. TTV_2는 TV-13의 설계를 단계별로 다시 확인한 셈이고, TV-13(869)을 넘지 못했다.
- 남는 빈칸은 하나다: **고구마에는 2단계에 더할 상한 흔적이 없다.** 고구마의 상한 곳 지도를 만들어 2단계에 넣는 것은 사진과 CLIP 패치 특징이 필요하며 아직 하지 않았다.
- 읽을 때의 주의는 위 TTV_1과 같다. 개발 사진에서 본 경향이다.
