# CLIP 글 설명으로 거르기 보강 (τ 0.8로 묶은 ZS8을 시험지 T3로 다시 시험해 TV-12로 채택)

> **나중 결과 (2026-11-01):** 아래 첫 시험에서는 새 인터넷 시험지 기준에 1장 모자라 채택하지 않았다. 그 뒤 τ를 0.8로 묶은 후보(ZS8)를, 사진을 모으기 전에 채택 조건을 적어 둔 새 블라인드 테스트셋 [T3](../../results/t3_test/README.md)로 한 번 시험했다.
> - 다섯 채소 맞게 남김: 108 → 109
> - 새 채소: 31 → 31
> - 다섯 채소가 아닌 사진 거름: 41 → 48
> - 네 조건을 모두 통과해 **TV-12**가 되었다.
> - 예전 시험지에서 TV-12 점수: Test 287 / 285, 새 인터넷 시험지 199 / 188, "아무 사진" 216, 새 채소 시험지 176 ([`final_zs8.json`](final_zs8.json))

남은 약점(상한 과일 통과, 상한 고구마, 감자↔고구마 혼동, 밭에서 일부만 썩은 토마토)을 고치려고 시험했다. 규칙은 결과를 보기 전에 [`PREREG.md`](PREREG.md)에 적었다.

**결론:**
- "아무 사진"과 상한 과일은 좋아졌다(205 → 216장).
- 하지만 새 인터넷 시험지의 맞게 남긴 수가 189 → 186장으로, 기준(187장)에 1장 모자랐다.
- 그래서 이때는 TV-11을 그대로 썼다.
- 줄어든 주원인은 감자를 고구마로 보내는 일이 늘어난 것이다(4 → 7장).

## 방법

- 지금 거르기 점수(CLIP 분류기의 "다섯 채소가 아님" 로그 오즈)에 **α × e**를 더했다.
- e는 학습 없이 CLIP이 원래 아는 글 설명으로 계산한다.
    - e = logsumexp(과일 40·다른 채소 27·물건 19 낱말) − logsumexp(다섯 채소 낱말)
- 거르기 기준(Valid + 실제 장면 채소 192장의 95% 통과)과 새 채소 분류기의 τ는 같은 규칙으로 다시 맞췄다.
- 상한 과일을 학습시킨 예전 후보 F1과 달리, 분류기는 다시 학습하지 않는다.

- **판정:** 새 인터넷 시험지의 맞게 남긴 수가 1장 모자라 채택하지 않았다.
- **원인:**
    - τ가 규칙에 따라 0.8에서 0.7로 내려갔다.
    - 거르기가 세지면서 다섯 채소 시스템이 거른 감자를 새 채소 분류기가 고구마로 가져가는 일도 늘었다.
    - 개발용 사진에서는 이 일이 1장만 늘었지만, 새 인터넷 시험지에서는 3장 늘었다.
- **상한 고구마와 밭 토마토는 그대로였다.** 이 방법으로는 고쳐지지 않았다.
- **채점 횟수:** Test 14번, 새 인터넷 시험지 9번, "아무 사진" 7번, 새 채소 시험지 6/5/4/3번이 됐다.

## 다음에 해 볼 수 있는 것

- **τ를 0.8로 묶고 같은 방법을 쓰기:** 감자→고구마가 늘어난 원인을 막는다. 다만 블라인드 테스트셋 결과를 보고 고친 것이 된다. 그래서 이 시험지들로는 공정하게 다시 잴 수 없고, 새 블라인드 테스트셋이 필요하다.
- 상한 고구마·밭 토마토는 학습 사진을 더 모으는 쪽이 필요해 보인다.

`evaluate.py`와 `final.py`는 작업 폴더에 저장해 둔 특징을 쓰는 기록용이다.
