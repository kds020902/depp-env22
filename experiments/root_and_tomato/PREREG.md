# 뿌리채소 "흙 묻음 vs 썩음"과 살짝 상한 토마토: 분류기 다시 학습 (결과를 보기 전에 적음, 2026-11-03)

## 사용자 요청 (2026-11-03)
> 1. 밭에 있는 거 굳이 하지 말고
> 2. 감자 / 고구마 / 양파 / 대파 등등 흙 묻은 거랑 썩고 곰팡이 핀 거 분류하기 + 토마토는 아주 약간 상한 거 (구글에 토마토 곰팡이 검색해서 이미지 학습시켜봐)

- **"밭" 부분:** 밭·휴대폰 사진으로 만든 "160장 시험지"를 지키는 조건에서 뺀다. 밭에서 찍은 사진은 새 학습 사진으로도 고르지 않는다.
- **"구글" 부분:**
    - 이 환경에는 구글 이미지 검색 도구가 없다. 구글은 자동 수집을 막고, 약관도 자동 수집을 금지한다.
    - 그래서 같은 목적의 공개 라이선스 사진을 쓴다. 공개 데이터셋(Kaggle·Roboflow, 상당수가 웹에서 모은 사진)과 iNaturalist, Flickr·Commons(접속될 때)의 "토마토 곰팡이", "썩은 감자" 같은 사진이다.

## 무엇을 바꾸나
- **다시 학습하는 것:** 두 분류기를 새 사진을 더해 다시 학습한다.
    - CLIP 분류기: 다섯 채소 10클래스 + "다섯 채소 아님"
    - 새 채소 분류기: 양파·고구마·대파 포함 16클래스 + "여덟 채소 아님"
- **그대로인 것:**
    - 채소 모델(EfficientNet-B0, `model.pth`의 가중치), 판정 규칙 `decide()`, 판단 보류(0.9)
    - 텍스트 근거(α 0.25)와 τ 0.8
    - 거르기 기준을 맞추는 방법: Valid + LVIS 실제 장면 채소 192장의 95%가 통과
    - 학습 방법: `src/train_clip_head.py`, 가벼운 워터마크 사본(정상 1.0 / 상함 0.25 / 아님 0.5), C=10
- 후보 이름은 **R1**이다.

## 기준 모델 B0′ (작업 폴더를 잃어서 필요함)
- 컨테이너가 다시 시작되면서 CLIP 분류기의 학습 사진을 잃었다.
- 다시 받은 사진은 4,623장 중 **4,591장**이다.
    - 출처를 알 수 없는 상한 당근 30장
    - Commons가 막은 2장
- 그래서 새 사진 없이 같은 방법으로 다시 학습한 **B0′**를 먼저 만든다.
- **보고하는 비교 두 가지:**
    - TV-12 대 B0′: 다시 만들기만 해서 생긴 차이
    - B0′ 대 R1: 새 사진의 효과
- **채택 기준은 TV-12와 비교한다.** 지금 쓰는 모델이 TV-12이기 때문이다.

## 새 학습 사진 ([new_train.csv](new_train.csv))
- **라이선스:** 공개 라이선스(CC0, CC BY, CC BY-SA, CC BY-NC, CC BY-NC-SA, PDM, MIT 등 데이터셋 표기)만 쓴다.
- **빼는 사진:**

    - 밭에서 찍은 사진(땅에 심긴 것, 밭 흙 위에 놓인 수확 장면)
    - 데이터셋 라벨과 사진이 맞지 않거나, 정상·상함이 섞인 사진
- **시험지와 겹치지 않게:**
    - T3·T4·T5·T6에 사진을 올린 사람과 그 관찰은 뺀다.
    - 학습에 넣기 전에 CLIP 코사인 0.95 이상인 사진을 뺀다. 비교 대상은 아래 사진이다.
        - T3·T4·T5·T6
        - 저장소 `dataset/`(Train·Valid·Test)
        - 개발 확인 사진
- **쓰지 않는 데이터셋:**
    - muhammad0subhan "Fruit and Vegetable Diseases": 다섯 채소 사진이 기본 데이터셋(muhriddin)의 원본과 같다. 확인한 결과 클래스마다 약 200장이 바이트까지 같다.
    - alibaloch "fresh and stale": 스톡 사진 축소본이라 alamy 등 워터마크가 보인다.
    - ketsaa "Pyaz mandi": 유튜브 영상을 캡처한 것이라 채널 로고가 있다. 라벨도 임의로 붙였다고 적혀 있다.
- **정답 붙이기:** 사진을 한 장씩 눈으로 보고 정답을 붙인다.
    - **정상:** 흙·먼지·작은 껍질 반점이 있어도 단단하고 썩지 않은 것
    - **상함:** 곰팡이, 무름, 썩음, 병해 반점, 싹 난 것(감자·양파·고구마)
    - **살짝 상한 토마토:** 작은 곰팡이, 작은 무른 반점, 배꼽썩음 초기도 "상함"이다.
- **모델로 후보를 거르는 경우:** iNaturalist 후보에서 식물·잎 사진을 덜어내는 데에만 CLIP을 쓴다. 학습 사진 후보를 고를 때만 쓰고, 시험지에는 쓰지 않는다. 마지막 정답은 눈으로 붙인다.

## 개발 확인 (T6를 열기 전)
- **개발 사진:** T3·T4·T5는 모두 이미 쓴 시험지이므로 개발 사진으로 쓴다.
- **TV-12 점수:** 저장소에 있는 TV-12 답으로 센 값이다. 다시 돌려도 같은지 확인한다.

| 볼 것 (T3+T4+T5) | TV-12 | 기준 |
|---|---:|---|
| **정상 감자 맞힘** | 19/44 (43%) | **+5장 이상** (24/44 = 55% 이상) |
| **상한 토마토 맞힘** | 16/28 (57%) | **+3장 이상** (19/28 = 68% 이상) |
| 상한 감자 맞힘 | 31/35 | −2장 이내 |
| 정상 토마토 맞힘 | 48/50 | −2장 이내 |
| 양파·고구마·대파 종류 맞힘 | 49/61 (정상 양파 18/20, 상한 양파 9/11, 정상 고구마 11/17, 대파 11/13) | −2장 이내 |
| 상한 과일 거름 | 34/83 | −3장 이내 |

- 양파·고구마는 "상태까지 맞힘"도 함께 보고한다.
- **지키는 조건 (예전 8개에서 160장 밭 시험지를 뺀 7개):**
    - Valid 맞게 남김: −3 이내
    - 첫 인터넷 시험지 221장 맞게 남김: −3 이내
    - 아시아 오이 37장: −2 이내
    - 일상 사진 400장 거름: −5 이내
    - 새 채소 Valid 종류 맞힘: −2 이내
    - 예전 채소를 새 채소로 답함(Valid·221·아시아 37·LVIS): +1 이내
    - 짝 클래스(상한 감자·정상 토마토): 위 표의 기준
- **지키는 조건의 사진:** Valid·인터넷 221·아시아 37·일상 400·새 채소 Valid 89·LVIS 192는 사진을 다시 받지 않는다. [`head_data.npz`](../new_vegetables/v7/head_data.npz)에 저장된 CLIP 특징과 채소 모델 출력을 쓴다. 같은 이미지 모델이고 채소 모델도 같아서 결과가 같다.
    - 지금 Flickr·Wikimedia가 이 컨테이너를 막고 있다(HTTP 429).
    - 160장 밭 시험지와 과일 374장은 참고로만 보고한다.
- **T3·T4·T5:** 사진을 다시 받아서 잰다. 끝내 받지 못한 사진은 모든 모델에서 똑같이 빼고, 몇 장으로 쟀는지 적는다.
- **판정:**
    - 정상 감자와 상한 토마토 중 하나 이상이 기준을 넘고, 나머지 조건을 모두 지키면 T6로 간다.
    - 둘 다 못 넘으면 "효과 없음"으로 적고 T6는 열지 않는다.
- 개발 결과를 보고 사진이나 설정을 바꾸면, 바꾼 내용을 이 파일에 먼저 덧붙이고 다시 잰다. 이렇게 한 번 고친 후보는 R2라고 부른다.

## 덧붙임 1: R1 개발 결과와 R2 (R2를 만들기 전에 적음, 2026-11-03)
- **R1 결과** ([dev_results_R1.json](dev_results_R1.json)): 기준을 넘지 못해 T6로 가지 않는다.
    - 정상 감자는 19 → 24/42로 기준(+5)을 넘었다. 양파·고구마·대파 종류도 49 → 53/61로 좋아졌다.
    - 상한 토마토는 16 → 16/28로 그대로였다.
    - 지키는 조건 세 개를 어겼다.
        - 상한 감자 31 → 27/35 (−4)
        - 인터넷 221장 190 → 185 (−5)
        - 예전 채소를 새 채소로 답함 1 → 4 (+3)
- **원인 (개발 사진을 보고 찾음):**
    1. 실제 장면의 싹 난·썩은 감자 8장이 "정상 감자"로 바뀌었다. 새로 넣은 실제 장면 감자가 정상 49장, 상함 15장으로 한쪽에 쏠렸다.
    2. 감자 사진 몇 장이 "고구마"로 바뀌었다. 새 채소 분류기에는 고구마 사진만 더하고 새 감자 사진은 더하지 않았다.
    3. 새 토마토 90장은 대부분 흰 배경·실험실 사진이라, 실제 장면의 상한 토마토에 효과가 없었다.
        - TV-12가 놓친 개발 사진은 실제 장면 사진이다. 하얀 솜털 곰팡이, 작은 반점, 줄기에 달린 채 상한 것 등이다.
        - 인터넷 221장에서는 상한 토마토 3장이 "상한 피망"으로 바뀌었다.
- **R2에서 바꾸는 것 (모두 사진을 더하는 방법이다. 설정·기준은 그대로다):**
    1. 실제 장면의 썩은·싹 난 감자를 iNaturalist 후보(같은 규칙)에서 더 골라, 실제 장면 감자의 정상·상함 수를 비슷하게 맞춘다.
    2. 새 감자·토마토 사진을 새 채소 분류기의 학습에도 넣는다. 그 분류기도 16클래스 전체를 배우기 때문이다.
    3. 실제 장면의 곰팡이 핀·살짝 상한 토마토를 iNaturalist 곰팡이 관찰에서 고른다.
        - 대상은 잿빛곰팡이 Botrytis cinerea, 거미줄곰팡이 Rhizopus stolonifer, 푸른곰팡이 Penicillium이다.
        - 규칙은 같다: T3~T6 관찰자 제외, 밭·줄기에 달린 것 제외, 눈으로 정답, 중복 검사.
- **R2 규칙:** 개발 기준과 지키는 조건은 위와 같다.
    - R2가 마지막 수정이다.
    - R2도 기준을 넘지 못하면 "효과 없음"으로 적고 T6는 열지 않는다.

## 덧붙임 2: R3 = 흙 묻은·썩은 감자 사진만 (만들기 전에 적음, 2026-11-04)
- **사용자 질문:** "여태까지 한 것 중 개선된 것만 넣을 수 있나, 넣으면 TV-12에서 얼마나 좋아지나"
- **효과가 있었던 것:** 흙 묻은 감자(정상 감자 45% → 60%, R1·R2)뿐이다.
    - R2의 부작용(상한 과일 거름 −5)은 곰팡이 토마토를 함께 넣으면서 생긴 것으로 본다.
    - 대파 없애기(G1)와 토마토 조각 검사(C1)는 블라인드 확인에서 탈락했다.
- **R3에서 바꾸는 것:** R2 사진 중 감자 사진만 넣는다.
    - 정상 감자 60장, 상한·싹 난 감자 49장
    - 토마토·양파·고구마·대파 사진은 넣지 않는다.
- **그대로인 것:** 방법은 R2와 같다.
    - CLIP 분류기는 B0′ 방법 + 감자 사진으로 학습한다.
    - 새 채소 분류기에도 같은 감자 사진을 넣는다(R2와 같은 이유).
    - 거르기 기준, 텍스트 근거, τ 0.8도 R2와 같다.
- **개발 기준:** 위의 표와 지키는 조건 7개를 그대로 쓴다(TV-12 대비).
    - 단, 상한 토마토 +3은 이번 목표가 아니므로 기준에서 뺀다.
    - 정상 감자 +5를 넘고 나머지를 모두 지키면 "개발 통과"다.
- **블라인드 확인을 할 수 없다.** T3~T7은 모두 이미 썼다.
    - T6(정상 감자 29장, 상한 과일 40장)를 **두 번째로, 참고로만** 다시 잰다. 이 결과로 R3를 고치지 않는다.
    - 반영(TV-13)은 사용자가 정한다. 블라인드 확인이 없다는 점을 함께 보고한다.
