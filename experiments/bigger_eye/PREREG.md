# CLIP 자리에 더 좋은 이미지 모델 넣기: 계획 (결과를 보기 전에 적음, 2026-11-03)

## 배경
- 웹 사진을 더 넣는 실험은 다섯 번 모두 효과가 거의 없었다(more_data, pepper_web, weak_spots, t3_weak_spots, balanced_clip_head).
- 막힌 곳은 사진을 숫자로 바꾸는 부분(CLIP ViT-B/16)으로 본다. 예: 당근 주름을 상한 자국으로 보고, 검게 쪼그라든 오이를 상한 감자로 본다(shape_and_parts).
- 채소 모델(EfficientNet-B0)과 판정 규칙은 그대로 둔다. CLIP 자리에만 다른 이미지 모델을 넣어 본다.

## 후보

| 이름 | 모델 (open_clip) | 사진 부분 크기 | 웹 데모(브라우저) |
|---|---|---:|---|
| B0 | ViT-B-16, DataComp-XL (지금 TV-12를 같은 과정으로 다시 만든 것) | 86M | 됨 (지금 88MB) |
| B1 | ViT-B-16-SigLIP2, WebLI | 93M | 됨 (8비트 약 95MB) |
| B2 | PE-Core-B-16, Meta | 94M | 됨 (8비트 약 95MB) |
| L1 | ViT-L-16-SigLIP2-256, WebLI | 약 300M | 안 됨 (PC용 predict.py만) |

- 글과 사진을 함께 다루는 모델만 고른다. 거르기("학습된 데이터가 아닙니다")와 새 채소 분류기가 글 설명을 쓰기 때문이다.
- L1은 B1과 같은 계열이라, 둘을 비교하면 모델 크기의 효과만 볼 수 있다.
- 이 컨테이너는 디스크가 작다. 후보마다 내려받기 → 특징 뽑기 → 가중치 지우기 순서로 한다. L1을 못 하면 못 했다고 적는다.

## 후보마다 똑같이 다시 만드는 것
1. **CLIP 분류기:** TV-12와 같은 사진과 같은 설정으로 다시 만든다.
    - 사진: Train 1,260장 + 추가 4,623장, 가벼운 가짜 워터마크 복사본 3,332장
    - 설정: C=10, 합치는 온도는 Valid로 맞춤
    - 거르기 기준: Valid와 실제 장면 채소 192장의 95%가 통과하도록 맞춤
2. **글 설명 거르기:** 같은 단어 91개와 같은 문장을 새 모델의 글 부분으로 다시 계산한다. α 0.25이고, 기준은 같은 규칙으로 다시 맞춘다.
3. **새 채소 분류기:** 같은 학습 줄 6,271개(경로를 복원함, [lists.py](lists.py))와 같은 문장, α 0.25로 다시 만든다. 기준과 τ는 같은 규칙으로 정한다.
4. **글 점수의 배율:** 지금은 100 × 코사인이다. 후보에는 각 모델이 학습 때 쓴 배율을 쓴다(B0·B2는 약 100, SigLIP2는 약 113). TV-12는 그대로 100이다.
- **먼저 할 확인:** B0로 이 과정이 TV-12와 같은 답을 내는지 본다. 같지 않으면 원인을 찾을 때까지 후보 결과를 보지 않는다.

## 비교 사진 (개발용만)
- **주 지표:** Valid 300장과 바깥 개발용 418장(인터넷 221, 160장, 아시아 오이 37)에서 맞게 남긴 수
- **같이 보고:** 판단 보류(0.9)를 켰을 때의 수치
    - 답한 수
    - 답한 사진의 정답률
    - 자신 있게 틀린 수
    - 상함을 정상이라고 한 수
- **지키는 조건 8개** (experiments/t3_weak_spots와 같음):
    - 맞게 남긴 수: Valid −3 이내, 인터넷 221 −3 이내, 160장 −3 이내, 아시아 오이 −2 이내
    - 일상 사진 400장 거름: −5 이내
    - 새 채소 Valid: −2 이내
    - 옛 채소 개발 사진이 새 채소로 바뀌는 수: +1 이내
    - 약점 개발 사진의 짝 클래스: −2 이내
- **참고로 보고:**
    - 상한 과일 761장 거름, 과일 374장 거름, 약점 개발 사진
    - Test 300 (틀린 사진을 이미 봐서 블라인드가 아님)

## 고르는 규칙
1. 지키는 조건 8개를 모두 통과한 후보만 본다.
2. **개선의 기준:** Valid와 바깥 718장에서 맞게 남긴 수가 TV-12보다 10장(약 1.4%p) 이상 많아야 한다.
3. 기준을 넘은 후보 중 가장 높은 것을 고른다. 단, B급 후보가 가장 높은 후보보다 5장 이내로 뒤지면 B급을 고른다. B급은 웹 데모에 넣을 수 있기 때문이다.
4. **고른 후보 하나만** 블라인드 테스트셋 두 개로 한 번씩 채점한다.
    - T3 137장: 반별 결과를 진단에 쓴 적이 있어 참고 성격이 섞인다.
    - T4 63장: 블라인드다.
    - 두 시험지를 합친 200장에서 다음 두 가지를 모두 지키면 반영을 제안한다.
        - 맞게 남긴 수가 TV-12(109 + 41 = 150) 이상
        - 상함을 정상이라고 한 수가 TV-12(8 + 9 = 17) 이하
5. 2를 넘는 후보가 없으면 블라인드 테스트셋은 쓰지 않고 "효과 없음"으로 적는다.
- **반영은 사용자가 정한다.** 반영하는 것은 `model.pth`의 CLIP 부분과 `predict.py`의 모델 이름이다. 웹 데모는 B급일 때만 바꿀 수 있다.
