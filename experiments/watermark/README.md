# 워터마크 지름길 (채택 안 함)

전문가 점검 2번 "워터마크 사진을 학습에서 빼거나 워터마크를 없애고 다시 학습"을 시험했다. 규칙은 결과를 보기 전에 [`PREREG.md`](PREREG.md)에 적었다.

**결론:**
- 지금 시스템(V7)은 **사진 위에 글자가 있으면 "상함"으로 기우는 지름길**을 실제로 배웠다. 채소 모델(EfficientNet-B0)에서 특히 크다.
- 정상·상한 사진에 가짜 워터마크를 같은 비율로 넣고 다시 학습한 **WB는 이 지름길을 거의 없앴다.** 하지만 160장 시험지에서 5장을 잃어 미리 정한 기준(3장 이내)을 넘지 못했다.
- 그래서 **V7을 그대로 쓰고**, 봉인 시험지는 채점하지 않았다. 채점 횟수는 그대로다(Test 12번, 새 인터넷 시험지 7번).

## 1. 워터마크가 얼마나 있나 (`valid_test_watermarks.csv`)

Valid·Test 600장을 한 장씩 눈으로 봤다. 스톡 사진 회사 표시, 사진 번호 상자(병해 사진 기관), 사진가 이름이 찍힌 사진을 1로 적었다.

| | 정상 | 상함 |
|---|---:|---:|
| Valid | 13 / 150 | 69 / 150 |
| Test | 10 / 150 | 71 / 150 |
| 합계 | **23 / 300 (8%)** | **140 / 300 (47%)** |

워터마크가 상한 사진에 몰려 있어서, 모델이 "글자 = 상함"을 배울 수 있는 데이터다.

## 2. 고치는 방법

워터마크 사진을 빼면 상한 학습 사진이 절반쯤 줄어든다. 그래서 대신 **학습할 때 가짜 워터마크를 찍되, 정상 사진에 더 자주 찍었다.** 그러면 워터마크가 정상과 상함 양쪽에 같은 비율로 있게 된다.

- **가짜 워터마크 (`src/watermark_aug.py`)**
    - 회사 이름 15개와 사진 번호를 쓴다.
    - 모양은 5가지다: 띠, 모서리 글씨, 비스듬한 큰 글씨, 번호 상자, 세로 글씨.
- **시험용 워터마크 (`stamps.py`, 학습에 쓰지 않음)**
    - S1: shutterstock 띠 + 큰 글씨. 모양은 학습에 있지만 이름은 없다.
    - S2: 반투명 "alamy" 글씨를 바둑판처럼 반복. 모양도 이름도 학습에 없다.
- **WA:** CLIP 분류기만 다시 학습했다. 학습 사진마다 복사본을 더하고, 복사본에 워터마크를 찍을 확률은 정상 1.0, 상함 0.25, 다섯 채소 아님 0.5다.
- **WB:** WA에 더해 채소 모델도 다시 학습했다(정상 0.6, 상함 0.3). seed 42·43 중 Valid 손실이 낮은 43을 썼다.
- **W0 (대조군):** 워터마크 없이 seed 42로 다시 학습했다. **지금 채소 모델과 가중치가 완전히 똑같이 나왔다.** 같은 설정이면 학습이 그대로 재현되므로, WB의 변화는 우연이 아니라 워터마크 증강과 seed 차이 때문이다.

## 3. 결과 (개발용 사진만, `dev_results.json`)

**지름길: Valid 정상 150장에 워터마크를 찍었을 때 "상함"으로 답한 수**

| | V7 (지금) | WA | **WB** |
|---|---:|---:|---:|
| 시스템, S1 | 7 → 15 (+8) | 7 → 12 (+5) | **6 → 4 (−2)** |
| 시스템, S2 | 7 → 18 (+11) | 7 → 15 (+8) | **6 → 9 (+3)** |
| 채소 모델만, S1 | 7 → 25 | 7 → 25 | 11 → 8 |
| 채소 모델만, S2 | **7 → 38** | 7 → 38 | 11 → 17 |
| CLIP 분류기만, S2 | 6 → 10 | 9 → 9 | 9 → 9 |

- 상한 사진에 워터마크를 찍어도 "정상"으로 바뀌는 수는 거의 늘지 않았다(1~3장).
- 지금 지름길은 대부분 채소 모델에서 생긴다. 학습에 없던 바둑판 글씨(S2)를 찍으면 정상 사진 150장 중 38장을 상함으로 본다.

**다른 성능 (8종 시스템 최종 답)**

| | V7 | WA | WB | 기준 (V7 대비) |
|---|---:|---:|---:|---|
| Valid 300장 (정확도 / 맞게 남김) | 291 / 287 | 291 / 287 | 292 / 288 | −3 |
| 인터넷 채소 221장 | 198 / 190 | 201 / 192 | **203 / 194** | −3 |
| 160장 시험지 맞게 남김 | 150 | 148 | **145 (탈락)** | −3 |
| 아시아 오이 37장 맞게 남김 | 30 | 32 | 31 | −2 |
| 인터넷 과일 374장 / 일상 400장 거름 | 337 / 400 | 337 / 400 | 337 / 400 | −10 / −5 |
| 새 채소 Valid 89장 | 78 | 78 | 78 | −2 |
| 워터마크 없는 Valid 218장 맞게 남김 | 209 | 209 | 208 | −2 |
| (기록) 워터마크 있는 정상 사진 13장 | 9 | 9 | **11** | – |
| (기록) 워터마크 없는 상한 사진 81장 | 80 | 79 | 78 | – |
| (기록) 채소 모델만 Valid 300장 | 281 | 281 | 272 | – |

- **판정:**
    - WA는 지름길 기준(D1)에서 탈락했다. 채소 모델을 그대로 두었기 때문이다.
    - WB는 160장 시험지만 기준을 넘지 못했다. 나머지는 모두 통과했다.
    - 통과한 후보가 없어서 봉인 시험지는 채점하지 않았다.
- **WB가 160장 시험지에서 잃은 5장**
    - 4장은 정상 사진(오이 1, 피망 2, 감자 1)을 상함으로 봤다. 새 채소 모델은 정상으로 봤지만 확신이 낮았고(0.51~0.87), 합친 답이 상함으로 바뀌었다.
    - 1장은 상한 감자를 정상으로 봤다.
- **대가:** 워터마크를 넣고 학습하면 채소 모델 혼자의 Valid 정확도가 내려갔다(seed 42: 271, seed 43: 272, 지금 281). 워터마크 없는 Valid 사진(207 → 203)에서도 내려갔으므로, 지름길이 없어진 탓만은 아니다.

## 4. 뜻과 다음에 해 볼 것

- **Test 점수를 볼 때 주의할 점이다.** Test 상한 사진의 47%에 워터마크가 있다. 채소 모델의 지름길이 Test 점수를 일부 도왔을 수 있다.
- **사용자 사진에도 해당한다.** 글자나 로고가 있는 사진(스크린샷, 쇼핑몰 사진)은 정상인데 "상함"으로 나올 수 있다.
- **다음에 해 볼 만한 것 (아직 안 함):**
    - 워터마크를 더 작고 약하게 찍기 (지금은 번호 상자·띠가 채소를 가리는 경우가 있다)
    - 지금 채소 모델에서 출발해 워터마크를 넣고 짧게 미세조정하기
    - seed 2개 모델의 평균

## 다시 돌리기

```bash
# 워터마크를 넣은 학습 (Test를 뺀 목록으로)
python src/train.py --manifest manifest_notest.csv --out WB_s43 --arch efficientnet_b0 --num-classes 10 --mode finetune --epochs 30 --patience 8 --threads 4 --seed 43 --watermark-fresh 0.6 --watermark-rotten 0.3
# 워터마크 복사본을 더한 CLIP 분류기
python src/train_clip_head.py --model WA.pth --extra-photos lvis_vegetables --extra-train extra_train.csv --clip-check-only --watermark-fresh 1.0 --watermark-rotten 0.25 --watermark-other 0.5 --feature-cache head_features.npz
```

`build.py`(후보 조립: 보정, 히트맵 배율, τ), `evaluate.py`(개발용 확인), `final.py`(마지막 채점, 이번에는 돌리지 않음), `common.py`, `stamps.py`는 작업 폴더의 사진 경로를 담고 있어서 기록용이다.
