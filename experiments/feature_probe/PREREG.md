# feature_probe — 특징 안에 정보가 있는가 (사전 등록)

결과를 보기 전에 커밋한다.

## 질문

두 번째 분류기가 쓰는 CLIP ViT-B/16 특징(512차원)만으로 아래 두 무리를 가를 수 있는가?
가를 수 있으면 문제는 분류기·데이터 비율 쪽이고, 못 가르면 특징 추출기 쪽이다.

| 이름 | 무리 A | 무리 B | 왜 |
|---|---|---|---|
| P1 | 감자(2,3) | 고구마(12,13) | 종류 구분 |
| P2 | 상한 감자(3) | 상한 고구마(13) | 지금 가장 많이 틀리는 혼동 |
| P3 | 정상 고구마(12) | 상한 고구마(13) | 고구마 상태 |
| P4 | 정상 감자(2) | 상한 감자(3) | 흙 묻은 감자 문제 |

## 데이터

`experiments/new_vegetables/v7/head_data.npz`의 라벨 있는 묶음만 쓴다:
`train_*`, `dev_valid`, `dev_odev`, `dev_o160`, `dev_newval` (모두 이미 개발용으로 쓴 것).

쓰지 않는 것: T3~T9 시험지, 고구마 새 사진 628장(`sweetpotato_more`). 628장은 쓰임이 정해지지 않았다.

## 방법

- 특징을 길이 1로 맞춘다.
- 거의 같은 사진이 학습·평가에 갈라 들어가지 않게, 코사인 유사도 0.95 이상을 한 묶음으로 잇고 묶음 단위 5겹 교차검증을 한다. 3번 반복(시드 0,1,2).
- 분류기 세 가지:
  1. 선형(로지스틱 회귀, L2 1e-3, 클래스 균형 가중) — 지금 두 번째 분류기와 같은 체급
  2. kNN(k=10, 코사인) — 선형이 못 쓰는 정보가 있는지
  3. 제로샷(text16 프롬프트) — 학습 없는 기준선
- 지표: 균형 정확도, 그리고 무리 B 재현율.

## 판정 기준 (미리 정함)

- 선형 균형 정확도 **0.95 이상**: 정보가 충분하다 → 분류기·데이터 쪽을 고친다.
- **0.85 미만**: 특징 한계 → 특징 추출기 교체·미세조정 후보.
- 사이: 애매. 선형과 kNN 차이가 0.03 이상이면 비선형 분류기 후보.

## 한계

같은 출처 안에서의 교차검증이라 **현장 사진 성능의 상한**이다. 여기서 높게 나와도 현장에서 실패할 수 있다(분포 차이).
현장 일반화는 새 시험지(T10)로만 확인할 수 있다.
