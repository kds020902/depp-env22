# 데이터셋 설명 (2차, 1,200장)

사진 한 장을 보고 채소 종류(오이·감자·토마토)와 상태(정상·비정상)를 함께 맞히는 6개 클래스 데이터셋이다. 모든 분할에서 정상:비정상은 5:5이고, 클래스마다 Train 140 / Valid 30 / Test 30장이다.

## 폴더 구성

사진은 아래 구성표와 같은 모양으로, 분할(Train·Valid·Test)과 상태(P 정상·N 비정상)별 폴더에 나눠 두었다.

```
dataset/
├── train/
│   ├── P_fresh/     정상 420장
│   └── N_rotten/    비정상 420장
├── valid/
│   ├── P_fresh/     정상 90장
│   └── N_rotten/    비정상 90장
├── test/
│   ├── P_fresh/     정상 90장
│   └── N_rotten/    비정상 90장
├── manifest.csv     사진마다 분할·클래스·그룹·출처·해시
├── summary.json     클래스·분할별 수량, 출처 정보, 중복·세션 기준 요약
├── review/          눈 검수 기록 (1차 round1_review.json, 2차 v2_*.json)
└── tools/           두 Kaggle 원본으로 이 폴더를 다시 만드는 스크립트 (아래 "다시 만들기")
```

- **채소 종류:** 파일 이름 앞부분에 있다(예: `tomato_rotten_1201.jpg`). 한 폴더 안에서 오이·감자·토마토 순으로 정렬된다.
- **manifest.csv의 경로:** `image_path`는 이 `dataset/` 폴더 기준이다(예: `test/N_rotten/tomato_rotten_1201.jpg`).
- **분할 이름:** manifest의 `split` 값은 `train`·`val`·`test`이고, Valid 폴더 이름만 `valid`다.

## 구성표

| 구분 | Train | Valid | Test | 합계 |
|---|---:|---:|---:|---:|
| 정상 (P, Fresh) | 420 | 90 | 90 | 600 |
| 비정상 (N, Rotten) | 420 | 90 | 90 | 600 |
| **합계** | **840** | **180** | **180** | **1,200** |

| 채소 | 정상 Train / Valid / Test | 비정상 Train / Valid / Test | 합계 |
|---|---|---|---:|
| 오이 | 140 / 30 / 30 | 140 / 30 / 30 | 400 |
| 감자 | 140 / 30 / 30 | 140 / 30 / 30 | 400 |
| 토마토 | 140 / 30 / 30 | 140 / 30 / 30 | 400 |

- **Train:** 모델 가중치를 학습하는 데 쓴다.
- **Valid:** 학습 중 가장 좋은 epoch를 고르는 데만 쓴다.
- **Test:** 모델을 다 고른 뒤 마지막에 한 번만 채점한다.

사진별 분할·출처·해시는 `manifest.csv`, 클래스별 수량과 요약 수치는 `summary.json`에 있다.

## 출처

| 출처 | 사용한 사진 | 라이선스 | 비고 |
|---|---:|---|---|
| [Fruits and Vegetables Dataset](https://www.kaggle.com/datasets/muhriddinmuxiddinov/fruits-and-vegetables-dataset) (Kaggle, 버전 2) | 1,140 | CC0 | 3종 원본 3,601장 (오이 608/593, 감자 615/585, 토마토 604/596) |
| [Fresh and Rotten Classification](https://www.kaggle.com/datasets/swoyam2609/fresh-and-stale-classification) (Kaggle, 버전 1) | 60 | CDLA-Permissive 1.0 | 오이 정상 30 + 비정상 30 |

두 데이터 모두 인터넷 이미지 검색 등으로 모은 사진이라 스톡 사진 워터마크와 작은 썸네일이 섞여 있다. 1,200장 중 447장은 짧은 변이 224픽셀보다 작다.

두 번째 출처는 1번 출처의 오이 비정상 사진이 부족해서 추가했다. 1번 출처 오이 비정상은 원본 593장에서 중복을 빼고 보니 부패가 분명한 사진이 174장뿐이었다. 출처 자체가 정상/비정상의 단서가 되지 않도록 정상과 비정상을 30장씩 같은 수로 넣었다. 이 출처의 사진은 장식용 검은 삼각형 테두리 안에 들어 있어서, 공통 틀을 템플릿으로 계산해 안쪽 사진만 잘라 썼다(`preprocessing=frame_cropped`). 같은 출처의 토마토는 정상과 비정상이 서로 다른 틀을 써서, 틀 모양이 정답 단서가 될 수 있어 쓰지 않았다.

## 만든 순서

1. **1차 600장 재검수:** 1차 때 모델이 틀린 16장을 다시 보고, 라벨이 틀린 4장을 뺐다(멀쩡한 오이 3장, 얼굴이 그려진 감자 1장).
2. **후보 고르기:** 원본에서 1차 때 쓰지 않은 사진 중, 픽셀·해시가 같은 중복을 빼고 장면마다 1장씩 무작위로 골랐다. 쟁반 위 토마토를 회전시켜 늘린 복사본 258장은 다양성이 없어서 검수 전에 뺐다.
3. **눈으로 검수:** 1,053장을 한 장씩 보고 867장을 통과시켰다(1번 출처 957장 중 792장, 2번 출처 96장 중 75장). 기준은 아래와 같다.
4. **중복·장면 그룹 만들기:** 같은 사진의 복사본(반전·회전·잘라내기·워터마크만 다른 것)은 한 그룹으로 묶어서 서로 다른 분할에 들어가지 않게 했다.
5. **분할:** 클래스마다 Valid·Test 30장씩은 서로 다른 작은 그룹에서 뽑았다. 나머지에서 Train 140장을 채우되, 같은 촬영 세션 사진이 많으면 그 세션부터 줄였다.

최종 1,200장 중 519장은 1차 데이터에서 그대로 왔고, 681장은 새로 추가했다. 1차 사진 중 81장이 빠졌는데, 라벨 오류 4장과 세션 과다 정리 77장이다. 사진별 사유는 `review/v2_removed_from_v1.json`에 있다. 이 파일의 `image_path`는 1차 때의 경로다.

## 검수 기준

- **공통 제외:** 종류가 다르거나 불확실한 사진(피망·고구마·멜론 등), 조리·가공된 것, 여러 사진을 붙인 합성·설명 이미지, 일러스트, 정상과 비정상이 한 장에 섞인 사진
- **정상에서 제외:** 싹이 난 감자, 껍질이 초록색으로 변한 감자, 벌레 구멍이나 갈라짐이 있는 토마토
- **비정상 통과 조건:** 곰팡이·무름·갈변·주름(시듦)·병반·싹(감자) 같은 흔적이 사진에서 분명히 보일 것. 단순히 노랗게 익은 오이, 피클 병, 썰어 놓은 정상 오이는 제외

사진별 통과·제외 기록은 `review/v2_visual_review.json`에 있다.

## 같은 사진이 Train과 Test에 섞이지 않게 한 방법

원본 데이터에는 같은 사진을 반전·회전·잘라내기만 한 복사본이 많다. 아래 조건 중 하나라도 맞으면 같은 그룹(`group_id`)으로 묶고, 그룹은 통째로 한 분할에만 넣었다.

| 검사 | 기준 | 잡아내는 것 |
|---|---|---|
| 1차 그룹 | 1차 때 같은 그룹 | 1차에서 이미 찾은 반복 촬영 |
| 지각 해시 | pHash 거리 ≤ 6이고 dHash 거리 ≤ 8 | 거의 같은 사진, 크기만 다른 사진 |
| 반전·회전 불변 특징 | ResNet18 특징을 8방향(반전·90° 회전)으로 비교한 코사인 ≥ 0.92 | 좌우·상하 반전, 회전 복사본 |
| 특징점 매칭 | ORB + RANSAC 일치점 ≥ 30 (내용 유사도 ≥ 0.85일 때) | 잘라내기, 확대, 워터마크만 다른 복사본 |

비슷한 배경·구도의 사진 묶음(`session_id`)도 따로 만들었다. 유사도 0.90 이상으로 이어지는 사진들로, 대부분 같은 촬영 세션이지만 비슷해 보이는 다른 사진이 함께 묶이기도 한다. 30장 이상인 큰 세션은 Valid·Test에 넣지 않고 Train에만 썼다. 같은 토마토를 배경만 바꿔 다시 찍은 사진이 Test로 새지 않게 하기 위해서다. 한 세션에서 Valid·Test로 가는 사진은 클래스당 10장으로 제한했다(실제 최대 4장).

천·노트 배경 토마토 세션에는 정상과 비정상이 모두 있다. Train에 정상 42장, 비정상 42장으로 같은 수를 넣어서 배경이 정답 단서가 되지 않게 했다.

**검증 결과:** 분할 후 Valid·Test 사진마다 가장 닮은 Train 사진을 찾았다. 반전·회전 불변 유사도의 최댓값은 0.918이었다. 0.91 이상인 쌍을 눈으로 확인했을 때 모두 서로 다른 사진이었다.

## 라벨의 의미와 한계

- 정상·비정상은 원본 폴더 라벨(Fresh·Rotten)을 눈 검수로 걸러서 쓴 것이다. 비정상에는 부패 외에 시듦·상처·싹 난 감자도 포함된다. 이상 세부 유형(`abnormal_type`)과 이상 부위 표시(`region_annotation`)는 없다.
- 개체 단위 ID가 없어서, 같은 채소를 각도만 바꿔 찍은 사진이 서로 다른 분할에 들어갔을 가능성은 남아 있다. 위 방법은 같은 사진의 복사본을 막는 것이지, 같은 채소의 다른 사진까지 완전히 막지는 못한다.
- Test도 인터넷 사진이다. 직접 찍은 사진에서의 성능은 아직 측정하지 않았다.
- 토마토 정상 Train 140장 중 83장은 두 촬영 세션(쟁반 41장, 천·노트 배경 42장)에서 왔다. 1번 출처에 다른 토마토 정상 사진이 더 없었다.

## 다시 만들기

`tools/build_dataset_v2.py`는 두 Kaggle 원본과 검수 기록(`review/`)으로 이 데이터셋을 같은 폴더 구성으로 다시 만든다. 사람이 한 눈 검수 결과는 `review/v2_visual_review.json`에 저장돼 있어서 다시 검수할 필요는 없다. 명령은 저장소 맨 위 폴더에서 실행한다.

```bash
pip install -r requirements.txt

# 1) 원본 내려받기 (Kaggle 로그인 없이 받을 수 있는 공개 데이터)
curl -L -o fv.zip "https://www.kaggle.com/api/v1/datasets/download/muhriddinmuxiddinov/fruits-and-vegetables-dataset?datasetVersionNumber=2"
curl -L -o fs.zip "https://www.kaggle.com/api/v1/datasets/download/swoyam2609/fresh-and-stale-classification"
unzip -q fv.zip -d src1
unzip -q fs.zip 'dataset/*/freshcucumber/*' 'dataset/*/rottencucumber/*' -d src2

# 2) 1차 manifest 꺼내기
git show 03db425:manifest.csv > v1_manifest.csv

# 3) 다시 만들기 (CPU 4코어 기준 약 10~15분)
python dataset/tools/build_dataset_v2.py --src1 src1 --src2 src2 --v1-manifest v1_manifest.csv --out rebuilt
```

결과는 이 폴더와 같은 구성(`rebuilt/train|valid|test/P_fresh|N_rotten/`, `rebuilt/manifest.csv`)으로 나온다. 순서는 다음과 같다.

1. 1차 사진 중 라벨 재검수로 뺀 4장을 제외한다.
2. 눈 검수를 통과한 사진을 더한다. 두 번째 출처 오이는 테두리를 잘라낸 뒤 정상·비정상 30장씩 고른다.
3. 지각 해시, 반전·회전 불변 ResNet18 특징, ORB 특징점 매칭으로 같은 사진의 복사본을 한 그룹으로 묶는다.
4. 클래스마다 Train 140 / Valid 30 / Test 30으로 나누고, 분할과 상태별 폴더에 저장한다.

이렇게 다시 만든 결과는 저장소의 `manifest.csv`, 사진 1,200장과 바이트 단위로 같다.
