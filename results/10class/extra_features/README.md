# 추가 기능: 상한 곳 표시, 다시 찍기 안내, "가장 가까운 것" 알려주기

`src/predict.py`와 데모 페이지에 세 가지 기능을 더했다. 모델 가중치와 판정(종류·상태, "학습된 데이터가 아닙니다")은 바뀌지 않는다. 판정 결과에 설명을 덧붙이는 기능들이다.

| 기능 | `predict.py` | 데모 페이지 |
|---|---|---|
| 상한 곳 표시 (히트맵) | `--heatmap 폴더` | 결과가 나오면 사진 위에 자동으로 표시, 버튼으로 끄고 켜기 |
| 다시 찍기 안내 | 항상 (`retake` 열, 기준은 `--retake-below`) | 확신이 낮을 때 안내 문구 |
| 가장 가까운 것 알려주기 | `--clip-hint` (선택) | 없음 (CLIP 모델이 커서 브라우저에서 돌리기 어렵다) |

## 1. 상한 곳 표시 (히트맵)

모델이 "상했다"고 본 부분을 사진 위에 빨갛게 칠한다. 진할수록 그 부분이 "비정상" 쪽으로 강하게 밀었다는 뜻이다.

**만드는 법**
- 모델의 마지막 특징 지도(7×7칸)를 쓴다.
- 칸마다 "비정상" 점수를 "정상" 점수보다 얼마나 높였는지 계산한다. 예측한 채소의 비정상 클래스와 정상 클래스를 비교한다.
- 지금 모델은 평균 풀링 바로 뒤에 분류층이 있다. 그래서 이 값은 근사가 아니라 각 칸이 점수 차이에 정확히 기여한 몫이다(class activation map, Zhou et al. 2016).
- 비정상 쪽 몫(양수)만 칠한다.
- 색의 진하기는 고정된 기준(17.06)으로 나눈다. 이 기준은 Valid 비정상 150장에서 가장 진한 칸 값의 중앙값이다(`model.pth`의 `rot_map.scale`).
    - 사진마다 가장 진한 곳을 최대로 맞추지 않으므로, 모델이 멀쩡하다고 본 사진은 거의 칠해지지 않는다.
    - Valid에서 가장 진한 칸 값의 중앙값은 정상 사진이 0.38, 비정상 사진이 17.06이다.

**상한 곳을 제대로 가리키는가 (`pointing_game.csv`)**
- 일부만 상한 사진 61장([partial_rot 실험](../../../experiments/partial_rot/README.md)의 확인용 세트)으로 확인했다.
- 히트맵을 계산하기 전에, 사진마다 7×7 격자를 그어 상한 칸을 눈으로 표시했다.
- 그다음 히트맵에서 가장 진한 칸이 표시한 칸 안에 떨어지는지 셌다(pointing game).
- 상한 부분이 채소 전체에 퍼진 4장은 따로 뺐다.
- 두 가지 지도 중 더 잘 맞는 것을 쓰기로 미리 정했다.

| 상한 부분이 일부인 57장 | 가장 진한 칸이 상한 곳에 떨어진 수 |
|---|---:|
| **상한 곳 지도 (비정상 − 정상, 채택)** | **39 (68%)** |
| 예측한 클래스 지도 (일반 히트맵) | 37 (65%) |
| 사진 한가운데 칸 (비교용) | 27 (47%) |
| 무작위 칸 (기댓값) | 약 8 (13%) |

- 예시는 `examples_partial_rot.jpg`에 있다. 왼쪽은 원본, 오른쪽이 히트맵이다.

**한계**
- 7×7칸이라 작은 반점의 정확한 위치보다는 "대략 어느 쪽"을 보여 준다. 채소가 사진의 작은 부분이면 채소 전체가 칠해지기도 한다.
- 모델이 정상으로 본 사진(예: 꼭지 둘레만 상한 토마토)은 칠해지지 않는다. 히트맵은 모델의 판단을 보여 줄 뿐, 놓친 부분을 찾아 주지는 않는다.
- 상한 곳은 한 사람이 눈으로 표시했고, 격자 칸 단위라 경계가 거칠다.
- 데모 페이지의 브라우저 엔진으로 같은 사진을 계산하면 PyTorch와 소수점 셋째 자리까지 같았다.

## 2. 다시 찍기 안내

이 판정의 확률(보정된 확률)이 **90% 미만**이면 다음처럼 안내한다.

> 확신이 낮습니다. 채소 하나만, 밝은 곳에서, 상한 부분이 보이게 가까이 다시 찍어 보세요.

"학습된 데이터가 아닙니다"로 거른 사진에도 다시 찍기를 권한다.

**처음 계획: 사진 품질로 안내하기 (쓰지 않음)**
- 사진이 어둡거나, 지나치게 밝거나, 흐리거나, 너무 작으면 안내하려고 했다.
- 기준은 Train·Valid 1,560장의 분포에서 미리 정했다.
    - 밝기(224×224 회색조 평균)가 하위 2%(66.4)보다 어둡거나 상위 2%(234.9)보다 밝을 때
    - 선명도(라플라시안 분산)가 하위 2%(24.5)보다 낮을 때
    - 짧은 변이 100픽셀보다 작을 때 (학습 사진도 5%가 100픽셀이라 그보다 작을 때만)
- 인터넷 사진으로 확인해 보니, 경고가 뜬 사진을 모델이 오히려 더 잘 맞혔다(`quality_check.csv`).

| | 경고가 뜬 사진 | 경고가 없는 사진 |
|---|---:|---:|
| 인터넷 채소 221장 | 13/15 맞음 (87%) | 154/206 맞음 (75%) |
| 160장 시험지 | 13/13 맞음 (100%) | 135/147 맞음 (92%) |

- 지금 모델이 틀리는 이유는 사진 품질이 아니라 내용(밭에서 상한 토마토 등)이었다. 이 경고는 사람을 헷갈리게 할 뿐이라서 쓰지 않았다.

**대신: 모델의 확신으로 안내하기 (`retake_by_confidence.csv`)**
- 기준 90%는 Valid에서 정했다. Valid에서 확률이 90% 이상인 사진과 미만인 사진의 정답률 차이가 컸다.

| 거르지 않은 사진 | 확률 90% 이상 | 확률 90% 미만 (안내가 뜸) |
|---|---:|---:|
| Valid 300장 | 243/249 (97.6%) | 35/48 (73%) |
| 인터넷 채소 221장 | 118/134 (88%) | 40/68 (59%) |
| 160장 시험지 | 126/132 (95%) | 20/26 (77%) |

- 인터넷 채소에서는 사진 3장 중 1장꼴로 안내가 뜬다. 그 사진들은 10장 중 6장만 맞으므로, 다시 찍을 가치가 있다.

## 3. "가장 가까운 것" 알려주기 (선택, CLIP)

"학습된 데이터가 아닙니다"로 거른 사진에, 그 사진이 무엇과 가장 비슷한지 덧붙인다.

> 학습된 데이터가 아닙니다 (사과로 보입니다.)

**만드는 법**
- [CLIP 문지기 실험](../../../experiments/clip_gate/README.md)과 같은 CLIP(DataComp ViT-B/16)과 같은 단어 90개를 쓴다.
    - 다섯 채소, 과일 40, 다른 채소 26, 그 밖 19개다.
- 가장 가까운 단어를 한국어로 알려 준다. 가장 가까운 것이 다섯 채소 중 하나이면 "○○와 가장 비슷하지만 모델이 확신하지 못했습니다. … 다시 찍어 보세요"라고 안내한다.
- 어떤 사진을 거를지는 바꾸지 않는다. 그 결정은 지금처럼 채소 모델이 한다.
- `pip install open_clip_torch`가 필요하고, 처음 쓸 때 모델(약 600MB)을 내려받는다. 사진 1장에 CPU로 약 0.2초가 더 걸린다.

**얼마나 맞는가 (`clip_hint_fruit.csv`)**
- 인터넷 과일 374장 중 지금 모델이 거른 101장에서, CLIP이 과일 이름을 맞힌 것은 80장(79%)이다. 귤/만다린, 배/서양배처럼 같은 과일의 다른 이름은 맞힌 것으로 셌다.
- 틀린 것은 대부분 닮은 과일이다. 레몬을 유자로 본 것이 5장이고, 오렌지를 귤로 본 것도 있다.
- 일상 사진(COCO) 중 거른 311장은 297장을 "사람·탈것·건물" 같은 그 밖의 것으로 봤다.
- **주의:** 진짜 채소가 걸러진 경우(인터넷 채소 19장)에는 7장만 다섯 채소로 봤다. 나머지는 상한 토마토를 "감"으로 보는 식으로 엉뚱한 이름을 댔다. 그래서 이 기능은 기본으로 켜지 않는다.

## 다시 돌리기

```bash
python src/predict.py --model model.pth --input my_photos --output results.csv --heatmap heatmaps
python src/predict.py --model model.pth --input my_photos --output results.csv --clip-hint   # open_clip_torch 필요
```
