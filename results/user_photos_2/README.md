- **읽는 법:** 사진을 더한 SP1은 분류기 안에서는 옳은 쪽으로 움직였다(고구마 1순위 3 → 7장). 하지만 답을 바꾸려면 새 채소 확률이 0.8을 넘어야 해서, 실제로 바뀐 답은 2장뿐이다.
- 즉 지금 구조에서는 **전환 규칙(0.8)이 병목**이다. 다섯 채소 시스템이 이미 "상한 감자"를 확신하고 있고, 새 채소 분류기는 그것을 뒤집을 만큼 확신해야만 답이 바뀐다.

## 다음 방향에 대한 생각 (추측, 사용자 결정)
- 지난번에 적은 "전환 기준을 0.9로 올리는 후보"는 **권하지 않는 쪽으로 바꾼다.** 이 결과를 보면 기준을 올릴수록 상한 고구마가 고구마로 넘어가기 더 어려워진다.
- 상한 고구마: 사진 추가는 방향이 맞지만 전환 규칙이 막는다. 다음 후보는 "사진 추가 + 전환 규칙을 고구마·감자 사이에서만 다르게"처럼 규칙을 건드려야 한다. 감자를 고구마로 보내는 부작용(개발에서 +3장)을 함께 봐야 한다.
- 흙 묻은 감자: 더 큰 문제다(83%를 상했다고 답함). 채소 모델을 다시 학습하지 않고 고치려면, 토마토 때처럼 "상한 감자" 답만 다시 확인하는 단계를 붙이는 방법이 있다(`experiments/tomato_crops`의 방식). 예전의 R3(감자 사진을 CLIP 분류기에 추가)는 T8에서 +1장에 그쳤다.
- 어느 쪽이든 계획을 먼저 적고, 개발 확인 뒤 T9로 판정한다. 이 60장은 이제 본 사진이므로 개발 사진으로만 쓴다.
