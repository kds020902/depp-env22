## 2026-11-20 · Codex 독립 전체 리뷰 — 예측·재현·평가

검토 기준은 작업 브랜치 [`74e7a46`](https://github.com/kds020902/depp-env22/commit/74e7a46)이다. 직전 리뷰의 데이터셋 공통화 판정은 유지한다. 이번에는 src, 실행 문서, 평가 스크립트, 결과 구조, 자동 테스트를 살폈다.

### 우선 고칠 것
1. **예측 출력에서 파일명 충돌과 실패 상태를 처리한다.** 재귀 입력의 `a/a.jpg`, `b/a.jpg`를 처리하면 CSV 두 행이 같은 히트맵을 가리키고 두 번째 이미지가 첫 번째 결과를 덮어쓴다. 또 입력이 전부 손상되어 0장 성공해도 CLI의 `main()`은 정상 반환한다. 상대 경로를 보존하거나 파일명을 고유하게 만들고, 0장 성공은 오류 상태로 반환하는 것이 좋다. [예측 루프](../src/predict.py#L213)
2. **HTML 설명을 실제 옵션과 맞춘다.** `--hold-back-below 0`에서도 안내에 90% 미만을 보류한다고 표시한다. 보정 정보 없는 체크포인트에서도 확률을 보정했다고 쓰는 문장이 고정돼 있다. CSV·콘솔과 같은 설정을 넘겨 실제 기준·보정 여부를 표시하면 된다. [보고서 안내](../src/predict.py#L182)
3. **재학습의 캐시와 출력 경로를 명시한다.** CLIP 특징 캐시는 사진 경로만 기본 키로 쓰고 모델·가중치나 파일 변경을 확인하지 않는다. 같은 차원의 다른 인코더를 넣고도 이전 특징이 그대로 반환되는 것을 재현했다. 또한 README의 EfficientNet 재학습은 `results/.../model.pth`에 쓰지만 다음 CLIP 명령은 루트 `model.pth`를 제자리에서 수정한다. 새 체크포인트 하나를 모든 단계에 넘기고, 실험 출력은 배포 가중치와 분리할 필요가 있다. [캐시](../src/train_clip_head.py#L42) · [저장](../src/train_clip_head.py#L156) · [README 명령](../README.md#L368)

### 검증과 문서
- **성적표와 기본 CLI는 다른 정책이다.** T3 채점은 `unknown`만 반영하고, 기본 CLI는 여기에 0.9 미만 판단 보류도 적용한다. 대표 점수에는 보류 적용 전 지표라고 표시하고, 이미 저장된 점수가 있을 때만 실제 응답 비율과 응답한 것의 정확도를 따로 계산하는 편이 좋다. 빠른 CI는 합성 특징으로 판정 함수를 확인하지만, 실제 CLIP이 포함된 기본 CLI 검증은 `FULL_TESTS=1`에서만 실행한다. 적어도 기본 경로의 배포 전 검증을 명시하자. [T3 채점](../results/t3_test/score.py#L87) · [CLI 테스트](../tests/test_project.py#L131) · [CI](../.github/workflows/tests.yml#L17)
